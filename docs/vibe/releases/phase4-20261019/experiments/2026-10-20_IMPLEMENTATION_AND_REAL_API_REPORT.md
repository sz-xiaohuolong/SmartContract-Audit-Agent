本轮把模型候选与程序操作的定位统一起来，增加可回查源码的权限事实，并接入有限的转账保护证明。2026-10-20，按用户选择的 `api/coding/v3` 完成一次四条件真实实验：16 次正式请求全部有效，零重试；另有 16 个计划单元因事实提示超限，在请求前共同阻断。

四个共同有效目标上，四条件的 F1 均为 1.0，**没有观察到分类增益**。12 条新候选得到 8 条支持、0 条反驳、4 条未知。工程验证通过，但真实维护者修复的双向验收、独立标签和精确 token 公平仍有缺口；阶段整体继续为部分完成（PARTIAL），研究效果尚未验证（UNVERIFIED）。本次授权已经消费，不自动追加实验。

## 1. 本轮改进了什么

例如，模型指出一处提现操作后，系统先确认它对应当前源码中的哪一个调用，再检查相关权限和状态。位置能够确认但权限证据不完整时，结果保持未知；不能因为函数中有一条检查，就宣布漏洞猜想错误。

| 改进 | 已验证的结果 | 保留的边界 |
|---|---|---|
| 统一敏感操作定位 | 七条历史转账候选全部唯一绑定，实际工具双收据匹配 | 七条原候选仍未知；定位成功不等于漏洞得到证明 |
| 权限事实进入提示 | 检查、状态写入、调用入口和初始化关系可回查；显式开启后实际 Java 消费回执与冻结文本一致 | 事实索引不完整，本身不改变核验裁决；超限整体拒绝 |
| 扩展有限保护证明 | 原生转账的有限地址权限、直接布尔角色和永久关闭状态门经过有效／无效对照 | 最终反驳须显式绑定“未授权调用可达”属性；默认模型候选不自动补属性，复杂语义保留未知 |
| 区分执行和评价结果 | 搜索未命中、回滚、预算、环境等原因分别记录；候选支持、反驳、未知、失败保持完整分母 | 执行没有找到见证不推导安全；没有独立标签就不报告独立正确率 |
| 四条件受控比较 | 冻结全文、事实、历史案例、源码、构建产物和配置，核对实际消费回执 | 本轮是开发集探索，不能宣称独立泛化或方法有效 |

## 2. 一次实验的范围与完整分母

本次固定八个既有开发目标，各运行四个条件，共 32 个计划单元。D1 指预先冻结的历史漏洞／修复参考知识；D2 指对模型候选进行程序证据核验的后续流程。四条件使用相同全文、操作目录、D2、模型和输出上限，仅切换事实提示与 D1。

| 条件 | 代码标识 | 输入变化 |
|---|---|---|
| A 全文基线 | `P4_BASELINE` | 关闭新增权限事实和 D1 |
| B 全文加事实 | `P4_FACTS` | 在 A 上增加权限事实 |
| C 全文加 D1 | `P4_D1` | 在 A 上增加冻结的历史参考 |
| D 全文加事实与 D1 | `P4_FACTS_D1` | 使用与 B 相同事实、与 C 相同参考及顺序 |

无付费预检发现四个目标的事实正文超过 16384 UTF-8 字节。为保持共同目标，每个超限目标的四条件一同阻断，不截去关键事实，也不替换样本。
