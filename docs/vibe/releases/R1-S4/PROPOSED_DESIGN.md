# R1-S4 目标设计：正式知识库驱动的单样本审计链路

状态：`APPROVED`，2026-10-05。本文描述**拟实现**架构；用户已批准函数级工程试跑的追加边界，现有架构仍以代码和 `docs/vibe/TECH_DESIGN.md` 为准。对应需求见 [SPEC](SPEC.md)，方案选择见 [CHANGE_PROPOSAL](CHANGE_PROPOSAL.md)。

## 总体结构

沿用方案 A：`tools/experiment/` 负责本机目标登记、谱系、快照读取、运行编排、报告和 HTTP；`audit-mvp` 保持 Java 21 / Spring AI 2.0.1，负责 D1 检索、严格模型输出及工具解析。Python 与 Java 通过版本化 JSON 和受控子进程通信；不增加第二个独立服务或数据库表。页面是本机 HTTP 的只读展示与显式运行入口。

```text
已登记开发目标 ──源码摘要／组隔离──┐
                                    ├─同版 BGE 编码─正式 Milvus 召回─Java D1─证据包
激活 s1b_ 快照 ──完整性读回──────────┘                              │
                                                              结构化模型假设（至多一请求）
                                                                      │
                                                      Slither／可选 Mythril 工具证据
                                                                      │
                                                       D2 保护义务初版判断
                                                                      │
                                               持久化 JSONL／汇总─本机页面回看
```

## 边界和接口

### 目标登记与检索

目标注册器读取固定首批分配与 intake，重算源码 SHA-256，并用首批完整 ledger 和正式知识快照 manifest 检查项目、事件、补丁对、精确重复及已发现近克隆边。仅 `development`、源码核验通过、无知识侧关联的样本可运行。`AC-ASE-006/009` 可进行整份源码单次模型工程试跑，但事实提取器没有与正式访问控制知识对匹配的调用风险事实，D1 返回明确缺口；不得把空证据包说成成功条件绑定。`RE-SCRUBD-002` 因源码尺寸超限显示阻塞原因。当前没有正式准入的开发真值，所有试跑结果带 `researchEligible=false`。

`RE-SCRUBD-001` 的 `matchOrderWithReserve` 作为唯一函数级工程入口：用原始完整源码提取事实、定位第 608 行调用和运行工具；从完整源码按函数声明与配对花括号截取片段，保留原始行号及完整源码／片段 SHA-256，模型提示明确“只分析该函数，其他调用上下文未知”。若源码摘要、函数边界或提示字节预算有任一不符则拒绝运行。函数内部含分支，D1 条件绑定为 `UNKNOWN` 时仍应展示召回候选与未选原因；不能把空 D1 上下文补成模拟证据或完整合约结论。

原有 `recall_pool` 对目标必须出现在正式快照 manifest 的要求保持不变，以保护既有研究入口。新增**工程目标适配器**在外部完整 ledger 上校验目标后，生成仅含目标源码摘要、同一正式快照 ID 和同版 embedding 的检索请求；适配器不得写入快照或改变 `recall_pool` 的研究语义。Milvus 返回每条候选须经本地快照 ID、向量分数、文档 ID 和内容再校验；异常即拒绝。Java D1 输出 `facts`、候选绑定、选中上下文及未知理由。对于多风险事实，只选择注册清单明示的单个工程检查点；该检查点是**页面试跑范围**，不可流入研究标签或正式实验的自动检索。研究版完整扫描留给后续需求。

### 模型、工具与 D2

新增版本化 `HypothesisReply`：顶层 `schemaVersion="2"`、`hypotheses` 数组（0–3 项）；每项字段固定为 `vulnerabilityType`（`ACCESS_CONTROL` 或 `REENTRANCY`）、`contract`、`function`、`riskLine`（正整数）、`riskOperation`、`reason` 和 `evidenceIds`。模型可报告“未发现”，用空数组表示；不得直接输出“安全”。后端核对 JSON 无多余字段、风险行存在于目标源码、类别与单样本注册机制一致、证据 ID 出现在 D1 包中。无效结构、输出截断和空正文各自保留错误分类。现有 S0 三字段 `AuditResult` 与历史报告不修改；新模式使用独立命令入口和独立响应类型。

工具适配层复用 `ToolAnalyzer`／`ProcessRunner`。Slither 为默认本机证据源，可配置关闭或缺失；Mythril 为显式可选源。每个结果保存引擎、状态、工具版本、源位置／告警及耗时；只允许固定可执行文件配置，不接受浏览器路径。没有工具时 D2 仍可读取轻量程序事实，但缺证据的义务只能 `UNKNOWN`。工具失败与模型失败分别计数，零告警不改变模型为安全。

D2 初版以模型假设为**待核查主张**，以“保护是否覆盖该风险”为六项义务：主体一致、资源一致、检查先于风险操作、相关入口覆盖、状态版本正确、无已知绕过。每项带 `SUPPORTED/REFUTED/UNKNOWN`、源码行和工具／事实引用。只有存在可核查风险路径且至少一项必要保护被具体证据反驳时，漏洞主张可标 `SUPPORTED`；只有所有必要保护均有可核查支持且风险路径被阻断时，主张才可标 `REFUTED`；其余为 `UNKNOWN`。轻量事实对继承、分支、别名等返回 `PARTIAL/UNKNOWN` 时不得升格为证明。D2 不调用模型，不把假设判断当独立研究真值。若模型阶段失败，D2 不生成肯定或安全判断，最终 `UNRESOLVED`。

### 持久化与页面

新增 `.local/audit-runs/<runId>/`，其中 `plan.json` 固定样本、源码／分配／快照／catalog／模型／提示版本和请求上界摘要；`events.jsonl` 逐阶段记录启动、完成、失败且逐行同步；`sample.jsonl` 最多一条终态样本记录；`result.json` 是原子发布的页面视图，包含 `schemaVersion="1"`、阶段状态、证据引用、用量及失败／UNKNOWN 分母。完整模型原文可按现有安全规则仅留本机诊断文件，不经 HTTP 暴露。旧 `.local/mvp-runs/` 保留只读，绝不自动迁移或回填。

运行器只对从未有启动标记的运行发起模型调用。若进程在发起后中断，恢复逻辑发布 `FAILED/UNRESOLVED` 的可读记录并要求显式新运行；不得猜测供应商是否已经计费，也不得自动重试。历史读取和 JSONL 下载只访问磁盘。HTTP 新路由只允许白名单样本 ID 和 `mode=offline|real`，拒绝额外字段、超大体、非本机 Host／Origin，并使用单写者锁避免并发付费。页面用文本节点显示来自源码和模型的数据，避免把检索文本渲染为 HTML。

## 验证、上线和回退

验证矩阵覆盖：正式／演示集合混淆、指针篡改、Milvus 返回不完整或错分、目标源码改变或与知识同组、事实 `UNKNOWN`、模型缺字段／多字段／截断、Slither 缺失／超时／损坏输出、D2 六项证据不足、中断后恢复、历史读取零调用、并发与跨源请求拒绝。全部默认用本地假索引、HTTP 和子进程夹具；根 Maven 与 Python unittest 为必跑检查。真正的 Milvus、Slither、Mythril 和 DeepSeek 冒烟均须单独记录，不参与默认自动测试。

按垂直步骤交付：①正式快照与 D1 页面预览；②模型假设与工具证据；③D2、报告和回放；④整链离线人工验收。每步保持旧 `/mvp.html` 可用；新路由可单独停用，新文件只写 Git 忽略的独立目录，正式 Milvus 集合只读。只有实际完成且有新鲜测试证据的小版本才按仓库约定提交并同步；研究验证状态不因工程完成改变。
