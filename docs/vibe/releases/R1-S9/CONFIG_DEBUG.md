# 配置冻结根因调查

2026-10-10，复核反复发现配置消费差异，按 vibe-workflow 熔断规则暂停局部补丁，使用 investigate 协议调查。Git 稳定基点仍为 `0b40b4b`；当前源码与既有改动保留，不回滚。调查范围仅为 `tools/experiment/` 的配置捕获、Java 消费适配及测试；项目暂为 REPLAN_REQUIRED / ACTIVE。

已知复现：启动检查后模型等待期间改变工具文件，原代码会消费新配置；Python 仅按等号读取，而 Java 支持冒号、Unicode 转义与续行，能实际改变端点或吞掉追加凭证。前两类已通过失败用例确认并改为严格语法准入及属性重序列化。

第三项假设：Python 的 truthy 检查接受全空白环境凭证，但 Java `ProviderRegistry.resolve` 使用 `isBlank()`，将冻结值视为缺失；如果保留 `api-key-env`，Java 就能回退至实时环境。根因属于跨语言配置语义与环境回退，而非知识快照或模型接口。

验证方案：空白凭证必须拒绝；捕获有效环境凭证后移除环境回退键。用离线红绿用例和实际 Java Properties 消费验证，之后重跑完整回归与独立复核。只修改受影响的配置模块与测试，不更换生产端点或读取真实凭证。

调查结果：上述根因已通过新失败用例和 Java 实际配置消费确认；`_configuration_values` 现在拒绝全空白凭证，物化直接凭证后删除环境回退键。配置三项回归、本机 Java 模型/Slither 整链夹具及 Python 完整 245 项均通过，独立复核无剩余配置阻断。权限 600、失败清理和报告不含凭证均有测试证据。临时范围锁已按原 owner token 解除，调查状态 DONE，恢复正常验收；未执行任何付费请求。

持久经验：跨语言配置应以校验后的值重建，不能把原始配置与追加属性拼接；冻结凭证必须同时关闭环境回退。后续配置变更优先从捕获、解析、序列化、Java 消费四个边界核对，不以多次读取摘要代替快照。
