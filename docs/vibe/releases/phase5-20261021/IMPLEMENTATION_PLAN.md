# phase 5：对照查询与证据区分度重排优化计划

本计划要回答：历史案例虽然和待审合约很像，是否真正解释了同一调用主体、资产和操作顺序？建议先在同一批历史材料上比较原查询与对照查询的得分，只改变材料排序，再检查选入提示的材料是否更有用。这样可以先评价检索环节，避免把更多模型请求、提示改写和证明器扩充同时算成一种改进。

## 1. 开工前确认什么

### 查询与评分契约

**查询构造。** 实现接口为 `build_queries(facts, binding, config) -> dict`，不接受目标真值、评价标签或目标修复身份。配置固定模板版本、维度白名单及每个原查询最多 3 条对照；这是首期工程上限，不是已证实的最佳参数。每条记录原查询、对照查询、唯一改变的维度、不变字段、事实 ID、源码跨度和编译收据摘要。

首期先支持两类可准确绑定的区别：访问控制中的检查主体（如 `msg.sender` 与 `tx.origin`），重入中的同一资源写入与外部调用先后。资源、入口、状态声明和回调前提其余部分保持不变。状态初始化、角色继承和跨合约资源未完整观察时，不生成看似完整的对照。多个操作不得只取第一项；按“目标＋事实 ID＋入口调用上下文”分别建查询，缺绑定者保留原因和分母。整个目标的查询预算在运行前冻结，超限操作逐项登记，不能静默丢弃。

结构检查只确认“问题改变了一个可定位维度”。它不保证未知程序上两个问题的答案不同，也不能把查询文字当作已修改合约。查询记录分别保存 `structureStatus` 与 `independentReview`：前者为 `VALID/UNSUPPORTED`，后者为 `UNREVIEWED/ACCEPTED/REJECTED`，分别表示结构有效／未支持、未审核／接受／拒绝。正式评价只使用独立接受的查询；结构有效但未审核者仅参加工程演练。无有效对照时为不可评分（`NOT_SCORABLE`），差值为空，不记为零分或安全。

**统一评分。** 实现接口为 `score_pool(query_set, evidence, encode, config) -> dict`。`e` 是冻结的完整前后机制窗口，沿用“改动前／后、未审核”表述；不能只取漏洞侧。所有比较条件使用相同文本和顺序，评分时不带目标标签、样本名称暗示或候选池原 dense 分数。首期复用选定本机编码器，以归一化向量余弦相似度计算 `s(q,e)`，并记录模型身份与输入前缀。该分数是检索代理指标，不是论文使用的评分器，也不是因果或程序证明。

对每个完整配对保存：

```text
originalScore(e) = s(q, e)
contrastScores(e) = [s(q′, e) for 每条有效对照 q′]
margin(e) = originalScore(e) − max(contrastScores(e))
```

同一个 `e`、同一个评分器产生全部分数。首期不混合 cosine、BM25 与模型概率，也不调整加权系数。固定负差值例子、逐材料取最大与先平均再取最大的反例，防止悄悄实现成论文附录或作者仓库的另一种公式。非有限数、维度错误、零向量、模型身份不符或编码截断均使该单元失败；不得补零继续排名。

机制窗口沿用原消费规则，明确标注省略了完整合约的其他上下文。编码器和下游提示各有上限：超限整体记录不可用，不静默截去保护条件。评分需要重新编码不同表达时，另存向量及输入摘要，不复用语义不相同的旧向量，也不覆盖活动快照。

**比较条件。** 实现接口为 `rank_pool(frozen_pool, scores, condition, budget) -> dict`。同池主比较只有两种排序：`P5_RELEVANCE` 按 `originalScore` 降序，`P5_MARGIN` 按 `margin` 降序；同分按稳定配对 ID 排序。首期关闭两侧的互补奖励，保持相同过滤、完整配对预算与渲染，仅替换排序键。phase 3 原 `R3_FUSION` 结果保留为工程参考，不能与不同候选池直接做单因素结论。

负差值只改变顺序，不触发新的拒绝规则。原候选池的全部条目、两种顺序、预算拒绝原因和未选条目均可回查。没有可评分对照时，原流程仍可单独运行并标明回退来源，但该目标不冒充新方法成功结果；覆盖与条件可运行性另列。不得只发布“能够评分”的平均成绩而隐藏其他目标。

**回执与兼容。** 每份新回执使用独立版本 `phase5-rerank-1`，记录 `sourceHash`、编译收据、`snapshotId`、`poolHash`、操作及入口上下文身份、配对材料摘要、查询与评分器配置摘要、全部分数、排序、选中 ID、文本摘要、预算、拒绝原因及原件指针。新文件由原子写入保存；失败不留下可误读为完成的结果。只读阶段不修改旧 schema；未来接入模型时，使用现有 `context` 与 `evidenceIds`，新增回执留在 Python 派生记录中。

### P5-01：只生成能够说明来源的对照问题

独立审核“区别是否有意义”与结构检查分开保存。测试通过同一函数注入目标标签、把样本名中的 safe／vulnerable 当提示、替换目标修复身份时均被拒绝；目标标签变化不能改变同一份事实构造出的查询。首期不让模型自由生成查询，也不为生成对照而修改真实合约。

### P5-02：在同一候选池上只改变排序

使用固定向量先写失败测试，分别钉住 `originalScore`、逐材料最大对照差值、负分、同分稳定排序和完整配对预算。然后实现 `score_pool` 与 `rank_pool`，复用现有材料渲染与冲突检查；必要的公共帮助函数只作窄提取，不重写原检索器。

两侧保持相同配对 ID 集、材料字节、评分器、查询和预算。预算可能使两侧最终入选数量不同，必须报告实际数量与长度，不能删掉这类结果。任一配对评分失败则该操作查询的比较单元失败，保留全部错误；不得只在新方法中跳过难评分材料。零向量、NaN、编码截断、身份漂移、缺一侧、预算不足和重复材料均有明确分支。

通过临时目录写盘、回读、重算，确认排序、文本摘要与回执一致。关闭新条件后原 `R3_*` 和 D1 结果不变。新方法与原方法使用不同派生目录，不覆盖原候选、评分或报告。

**验证：** 前述新测试，加上 `test_r3_retrieval.py`、`test_d1_consumption.py`、`test_formal_recall.py` 的相关回归。首次本机编码只在实现获准且模型身份检查通过后执行；真实编码证据与固定向量测试分开。编码器不可用则停止该集成检查，不能改用另一个模型冒充通过。

### P5-03：检验材料是否更有用，并公开失败和无增益

复用 `eval_ragas.py` 的人工相关性等级（0 无关、1 部分有用、2 直接有用）、审核人、依据和完整池检查，新增明确标识的配对级适配，不重定义旧片段成绩。查询独立审核与配对相关性分别登记，争议和未审核项保留；AI 诊断不能填写为独立审核。

主指标建议采用配对级 nDCG@k（衡量有用材料是否排在前面），辅助报告 P@k（前 k 项有用比例）、MRR@k（首个有用项的位置）和候选池 Recall@k（选中的有用项占该池有用项的比例）。这不是全知识库召回率。`k` 在评分前固定，不超过冻结消费上限；材料不足仍按原指标规则记录，不临时缩小分母。全部相关性为零时，沿用现有定义：P@k 为 0，召回率、MRR 与 nDCG 为空。

另外报告查询可评分覆盖、独立接受比例、各失败原因、实际入选数量与字节、编码次数和耗时。操作查询先在每个目标内取平均，再按目标汇总，避免操作多的合约支配结果；可评分操作与全部登记操作、完整目标与部分目标分别列数。共同可评分目标上的配对差异与全部目标覆盖同时展示，不给无标签目标编造分数。若做置信区间或显著性推断，须事先固定按项目／事件聚类的抽样单位、重复次数及多重比较规则；材料不足时只报告描述性差异。

干扰测试分两种：完全重复材料检验去重和确定性；不同来源但表面相似的材料检验实际干扰。先在夹具固定递增档位与材料，再在有审核的真实材料上复核。人工合成的干扰不混入独立真实样本成绩，不援引论文“数量不变性”作为免测保证。

**验证：** 新 CLI 及 `test_eval_ragas.py` 覆盖配对映射、完整池审核、全零、无标签、无对照、失败／未运行、共同分母与错身份。真实独立标签未取得时交付设施和未审核报告，方法效果仍尚未验证。主指标没有正向变化、保护相关材料更常被挤出、或只能靠事后挑样本得到增益时，停止推广并记录结果。

### P5-04：离线通过后，才比较模型发现

这不是首期实施的自动下一步。进入前需在 P5-03 报告中固定独立有效样本与增益判据，并补处理全文加事实超限和精确 token 预算问题。多个操作查询如何合并成一次目标审计的材料顺序，须先确定共同规则并做独立消融；首期离线任务不预设该规则。若只具备共同字节上限，应明确标为预算近似的探索，不能声称精确 token 公平或满足正式比较准入。

首个建议比较仅使用 `P5_RELEVANCE` 与 `P5_MARGIN`：候选池、配对表达、全文、目录、事实提示开关、模型、生成参数、D2 版本及输出预算相同，只让选中材料及其顺序随评分变化。生成结构和请求数相同，目标及执行顺序事前冻结。原 VANILLA、D1 或 R3 只能作另行预登记的辅助条件，不跨历史批次拼接成新对照。

调用前经现有 Java 提示构造器无付费预检，核对完整 system／user 消息与实际消费回执，记录源码、JAR、模型、端点和全部预算。任何条件超限须在采集前登记输入准入；阻断单元仍保留在完整计划中。不能通过删除关键检查、缩小待审源码或追加摘要请求来让一个条件过关。

报告发现的精确率／召回率／F1、函数和根因定位、D2 四态分布、错误支持与错误反驳、真实修复完整配对数，以及全部请求、重试、token、耗时和失败。缺独立候选标签时独立正确率为空。固定模型候选比较 D2、固定 D2 比较发现，两种问题分别解释；修复侧未报漏洞不自动等于程序证明反驳。

**验证：** `test_r3_protocol.py`、`test_benchmark_runtime.py`、`test_benchmark_batch.py` 及新增条件的本地 HTTP 集成。先证明无付费预检和回放可用，再在新的明确授权内实际执行；授权没有给出时到此保留计划，不调用。历史 `r3_cli.py` 的端点、八目标与单次授权文字不能当作 phase 5 授权。

### P5-05：多视角起草只作为后续独立消融

先用同一批、同样数量的模型请求比较普通重复起草与不同视角起草，避免把多调用收益算成分流收益。若正式提出该任务，需先确定分支数、候选合并和去重、相同总 token 与费用上限、任一分支失败的处理，以及是否存在额外仲裁请求；这些当前均未获范围或调用授权。

每个分支仍保留完整前后配对，防止漏洞与防御永久隔离而丢失比较依据。生成候选按源码位置、入口、属性和资源身份合并，每条候选保留来源分支并进入同一 D2。模型一致、低区分度、未找到见证和 D2 未知都不能互相替代。首期不引入谱聚类；若未来需要，须单独说明较现有互补选择的价值及可复现参数。

**通过条件：** 分支数与成本匹配的对照能够独立复算；格式失败与全部分支候选完整保留。没有证据证明额外复杂度有价值时停在 P5-03 或 P5-04，不以实现完整 CF-RAG 为目标。

## 5. 交付、恢复与停止条件

文档规划按现有约定检查后提交并同步 `origin/main`。未来工程小版本也在当前目录提交，只包含本任务文件；远程有新提交先整合并重验受影响范围。同步不代表 phase 5 工程完成、发布版本或上线部署。现有用户修改继续保留。

以下情况阻止进入后续任务：来源或收据不符、标签泄漏、错误事实绑定、静默截断、把失败补成有效分数、检索结果改变 D2 裁决、覆盖保护材料的退步没有解释、没有独立标签却宣称方法有效。任何真实模型或嵌入服务调用超出明确授权时停止，不自行更换端点续跑。
