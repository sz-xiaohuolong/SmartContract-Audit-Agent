# S2：D1 条件感知对比检索工程规格

日期：2026-09-21。Requirement Status：FROZEN（本轮工程范围）；Open Questions：None（工程行为）。用户本轮明确要求按 R0 S2 规划实现事实提取、D1、独立对照与离线验证，并授权使用本地 Milvus。正式数据配对与研究效果不随工程授权自动成立。

## 范围与验收

- D1-01：轻量 Python 事实提供器识别单文件合约状态变量、函数/调用主体、修饰器、状态写、外部调用及等值检查，保留源码摘要、位置和顺序。注释与字符串不提供事实；未支持语义显式 PARTIAL/UNKNOWN，不能把 onlyOwner 名称或 require 字样直接当作有效防护。
- D1-02：Java 主模块定义独立检索接口，使用同一个有版本的候选池与预算运行 Dense、Hybrid、普通正反例和 D1；不读取测试标签，不触发模型调用。
- D1-03：案例条件通过明确的角色绑定匹配当前目标的主体、资源、作用域与顺序。有效检查、错误主体、错误资源、检查过晚、分支/旁路和未知分别有解释。动态别名、未知控制流不按名称猜测。
- D1-04：D1 在候选召回后选择经审核的漏洞/防护配对，配对须同机制、相同风险操作、对应条件且至少一项保护条件相反。过滤条件矛盾的直接支持，未知项保留原因；没有合格配对或预算不足时明确缺口，不编造案例。
- D1-05：证据包输出候选池摘要、策略、预算、所选块、支持/对比角色、逐条件绑定、未知原因和配对缺口。同一案例不重复选块；四种策略使用相同文本计量方法，预算硬限制。
- D1-06：离线确定性测试覆盖上述条件和排序/配对/去重/预算。保持 Maven 与 tools/experiment 全套通过，更新 PROGRESS 和验证证据。

## 已授权边界

保留 Java 主工程与 Python 事实适配器的现有设计，直接在主目录开发，保留未提交修改。新增解释与注释为简体中文。不修改旧 Milvus 集合；本地服务联通试验使用独立命名实例与合成向量，不能依赖外部 embedding/模型。真实数据来源、配对标签、效果比较和费用预算仍须审核，不在本轮自动扩大模型调用。

事实提供器是受限词法/结构分析，不是 Solidity 编译器、CFG 或漏洞证明器。D1 判断案例适用性，不裁决目标安全。目标角色显式指定并检查来源，不按变量名猜测谁是合法权限主体；权限状态槽需要调用方明确绑定。D2、正式假设生成及下游付费实验保留后续阶段。
