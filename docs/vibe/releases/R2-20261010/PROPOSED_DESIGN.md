# R2 目标方案：先核对程序，再判断猜想

本页解释设计方向（PROPOSED）；当前已实现的行为以 [技术设计](../../TECH_DESIGN.md)、[实施计划](IMPLEMENTATION_PLAN.md) 和 [验收](VERIFICATION.md) 为准。方案沿用已确认 [规格](SPEC.md)，其中部分机制已实施，其余仍有缺口。

## 方案与顺序

先让每份目标可编译、可追溯，再使用真实 AST（代码结构）和 SlithIR（Slither 中间表示）检查猜想。受限语法提取保留为离线回退，负责解释可读结构和缺口；复杂程序语义仍要有编译与分析证据。本版本只扩展先导案例相关的有限机制。

模型与检索读取清理后的源码，评分读取单独保存的标签。原件、位置和任务类型分别登记；缓存对应完整源码与工具环境。这样后续可以分辨“模型发现发生了变化”和“同一候选获得了更多核验证据”。

## 验证与恢复

编译器和 Slither 各自产生独立收据，再核对源码、依赖、设置和产物一致。候选检查沿实际声明、资源键与相关入口追踪保护；只读入口的排除也需要编译语义依据。最终判断依赖可行反例或完整保护，不以调用方填写的结果字段代替证明。

模型、编译与工具接口使用本机夹具检查失败与成功路径。历史重放保留原批次，写新派生目录；不足的事实和入口仍是未知。实验身份与恢复规范见 [运行审计附录](attachments/OPERATIONS_AND_REPRODUCIBILITY.md)。

## SYNAPSE 启发的方案增补

[文献对照](attachments/SYNAPSE_REVIEW_20261014.md) 带来的工作统一进入 [SYNAPSE 任务](IMPLEMENTATION_PLAN.md#synapse-优化任务)，2026-10-14 首期结果见 [实施报告](experiments/2026-10-14_SYNAPSE_IMPLEMENTATION_REPORT.md)。

| 设计方向 | 目的 | 当前限制 |
|---|---|---|
| 发现与核验共用编译证据 | 避免相同代码在不同阶段获得不兼容的事实身份 | 同收据投影已接通；剩余语义缺口仍未知 |
| 从配对案例整理检查模板 | 把权限、资源和顺序问题对应到目标代码 | 10 条模板已有来源核对，独立语义审核为 0 |
| 提供函数与状态的焦点索引 | 帮助读者回查模型与验证器关注的代码 | 首期仍向模型提供 FULL 全文，语法回退没有完整证明能力 |
| 增加确定性证据复核 | 独立核对引用、入口、资源和正常提交 | 侧报告已接通，尚不改变 D2 三态 |
| 真实修复与正式研究对照 | 确认漏洞和正确修复都能得到可靠判断 | 独立标签、等 token 预算与真实修复双向结论仍未完成 |

业务状态一致性是后续范围提案。当前本机 EVM 只提供正常业务下的有限属性反例；不变量模板和多模型意见一致仍需独立程序证据才能形成结论。
