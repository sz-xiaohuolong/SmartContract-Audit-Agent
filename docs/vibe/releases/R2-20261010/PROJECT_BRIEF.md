# R2 需求基线：把审计结果变成可复核的研究证据

R2-20261010 延续已有命令行、固定知识快照和工作台，重点补齐访问控制与重入审计的输入治理、编译事实和候选核验。它服务于论文作者、答辩评审与接手工程的开发者。

## 问题与使用者

上一阶段的真实批次中，工具编译与事实覆盖不足，D2 全部未知。部分历史输入还带有答案注释，可能影响模型判断。读者需要知道一个告警是怎样提出的、检查了哪些代码、缺少哪些依据，而不只是看到一个风险标签。

本版本把原件、模型输入与评分标签分开；保存完整编译与工具依据；用新引擎重新核验历史候选，保留旧实验结果。程序可运行与方法效果分别记录。

## 范围、验收目标与约束

| 要完成的工作 | 对读者的意义 |
|---|---|
| 固定编译器并核对历史 53 个目标 | 相同代码与配置可以重复检查，失败有明确原因 |
| 清理答案注释，区分发现和候选核验 | 能判断实验是否向模型泄露了答案 |
| 提取 AST／Slither 程序事实并检查六项保护 | 风险定位、调用者、资产和执行顺序可以回查 |
| 重放保存假设并展示四臂对照 | 能比较同一批猜想在不同核验规则下的结果 |
| 盘点 10～15 个独立项目或事件 | 建立真实漏洞与维护者修复的来源依据 |
| 完成启动、演示和论文复现材料 | 开发者可以运行系统，评审可以核对结论 |

范围已确认（FROZEN），具体十二项行为只在 [规格](SPEC.md) 维护；目标方案、任务与验收分别见 [设计](PROPOSED_DESIGN.md)、[计划](IMPLEMENTATION_PLAN.md)、[验收](VERIFICATION.md)。
