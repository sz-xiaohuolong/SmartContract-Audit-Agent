## 问题与使用者

使用者为论文作者与审核者。R1 真实批次的工具编译和事实覆盖不足，D2 全部未知；历史评测输入还存在答案标注与真值选择泄漏风险。R2 在既有 CLI、固定快照、假设网关和工作台上补齐可复现证据，不用新的模型输出掩盖这些问题。

## 范围、验收目标与约束

- 固定编译器约束、参数、版本／摘要、耗时、退出和脱敏诊断；核验历史 53 个唯一目标。
- 分离原件、清理输入和评分真值，区分漏洞发现与给定候选核验。
- 评估编译器 AST／Slither IR，补齐先导相关事实与可核路径；D2 保留六义务、反例及未知范围。
- 对保存假设进行零新增模型请求的派生重放，原模型和原批次不覆盖。
- 盘点 10～15 个可核原件的独立项目／事件，记录真实 AC／RE 漏洞—修复与独立审核缺口。
- 完成 D1 离线检查、正式实验方案、工作台、演示／复现材料及逐项验收。

具体行为和十二项 REQ/AC 只在 SPEC 维护。新增模型请求预算为 0；历史报告、正式知识、旧源码与初始无关修改保留；不自动新增计费服务或公开部署。工程实现与研究有效性分别验收。
