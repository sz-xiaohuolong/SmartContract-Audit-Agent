# R2 行为规格：系统应当做到什么

本版本面向访问控制和重入审计，目标是让输入、检索、候选、工具分析和最终报告都能被复核。需求范围已确认（FROZEN），工程与研究分别验收。具体完成情况见 [验收矩阵](VERIFICATION.md)，任务顺序见 [实施计划](IMPLEMENTATION_PLAN.md)。

## 产品行为与验收接缝

系统应当允许读者选择或粘贴 Solidity，查看原始位置与参考案例，得到可以定位的漏洞候选，并看到六项核验和最终结论。已有结果可以重新检查、只读回放和导出。

下表沿用十二项需求编号。REQ 是需求，AC 是验收条件；“证明接缝”指要在哪个接口或测试中观察到行为成立。编号用于核对，不表示该项已经完成。

| REQ / AC | 必须成立的行为 | 证明接缝 |
|---|---|---|
| R2-01 输入与展示 | 预置真实样本、粘贴 Solidity、范围和原始行号可见；原件与清理输入能追溯 | 目标纯函数、工作台 HTTP、浏览器 |
| R2-02 工具环境 | 按全部有效 pragma 选择满足约束的固定编译器；记录版本/可得二进制摘要、参数、源码摘要、退出码、耗时与脱敏诊断；缓存绑定完整配置 | 本地编译器/子进程夹具；历史 53 个唯一目标真实核验 |
| R2-03 真值隔离 | 清理答案标注并保持位置；发现路径不用真值选函数、风险或检索；候选核验与发现明确区分 | 改变真值不改变发现输入/风险选择；模型和查询消费检查 |
| R2-04 D1 | 展示真实检索案例、配对、条件绑定与缺口；同池离线检查，正式实验固定完整提示 token 预算、标签和消融计划 | 固定快照夹具及本机查询；研究计划 |
| R2-05 假设 | 保留已有 Java schemaVersion=2 名称、风险操作、位置和引用绑定；拒绝项保持未决，模型未返回用量时保留未知（字段规则见运行审计附录） | loopback 模型网关及错位置/错机制夹具 |
| R2-06 程序事实 | 评估并复用编译器 AST/Slither IR，补齐先导所需旧语法、资源数据流、修饰器、简单分支、内部调用和相关入口；按证明范围记录完整性 | 编译器/IR 夹具及真实程序事实、引用回读 |
| R2-07 D2 | 展示六义务、可达/阻断路径与三态；正裁决需要可行反例及原工具佐证，负裁决需要完整保护；未覆盖仍未知 | 错主体/资源/顺序/入口反例；真实 AC/RE 各一组漏洞—真实修复正反裁决 |
| R2-08 派生重放 | 原批次、原模型和原结果不覆盖；派生结果绑定输入、代码、工具配置、原批次摘要；支持下载与只读回放 | 全部保存假设零模型重放；原件前后摘要；HTTP/浏览器 |
| R2-09 真实先导 | 目标 10～15 个可核原件独立项目/事件，来源、源码/修复版本、许可和审核缺口逐项登记；固定候选比较无验证、guard 存在、具体行与 D2 | 来源清单、固定挑战契约、从保存结果生成的错误/未知/覆盖/成本表 |
| R2-10 工作台交付 | 页面展示编译诊断、事实范围、D1、候选、六义务及原始/派生区别；单样本和批量口径一致，历史不发模型请求 | 实际 Chromium、下载文件、请求日志、注入边界 |
| R2-11 毕设材料 | 提供启动/演示/复现命令、系统实现、真实案例、实验口径和限制；数字由原始结果生成 | 文档链接与报告生成重算 |
| R2-12 交付 | 根 Maven、Python、CLI、新鲜本机工具与浏览器验证通过；逐小版本检查凭证、提交并同步 origin/main | 完整命令、评审、Git 与远程状态 |

## 状态与研究语义

工具运行成功表示产物可以读取；它没有回答候选是真是假。候选获得支持需要可行反例和匹配的工具佐证；被反驳需要完整保护证据。否则保持未知，并告诉读者缺少什么。工具超时、解析失败和缺少核验记录分别保留原因。

保护卡片评价保护条件，最终结论评价漏洞候选，两者含义见 [概念速查](attachments/CONCEPTS_AND_WALKTHROUGH.md#d2让六位审查官核对同一条猜想)。候选被排除的结论只适用于该候选，不能推广为整个合约的安全证明。

原始数据标签、自动知识标签、合成案例和独立候选审核分开使用。历史输入有答案标注风险；后来重新核验保存候选，不代表重新做了一次清理输入后的模型发现实验。没有独立审核时，研究资格仍为 `researchEligible=false`。

## 冻结的研究目标与当前结果

旧批次保留 159 个目标／策略单元、133 条原候选。未知数量最多 13 条是既有目标，2026-10-14 重放仍有 58 条，尚未通过；较严格的“13 条以下”也没有通过。历史 151 条与最新 163 条分别报告，不替换这个分母。

访问控制与重入各需一组真实漏洞和维护者修复的双向结论。目前 RabbitHole 与 Atomic 最终均未知；来源审核、独立真值、精确完整提示 token 公平和正式研究协议也还有缺口。详见 [实验看板](attachments/EXPERIMENT_DASHBOARD.md)。

焦点索引、10 条知识来源模板和确定性侧复核已接入工程。默认 FULL 源码与原 D1 配对仍是模型实际消费方式；模板 `BOUND` 仅表示槽位绑定，不表示修复正确或目标适用。

## 保留与兼容

Java 21、Spring Boot 4.1.1、Spring AI 2.0.1，当前只构建 `audit-mvp`；Python 位于 `tools/experiment/`。旧应用已退役，历史实现通过 Git 恢复。已有报告、正式快照、划分和原始候选保留，新输入不自动进入正式知识。
