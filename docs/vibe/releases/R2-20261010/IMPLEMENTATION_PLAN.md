#### SYN-01：让发现与候选核验消费同一编译证据

**问题与目标。** 最新163候选全部UNKNOWN，其中148条报告风险事实ID绑定失败；SimpleDAO同收据诊断已支持原候选。`compiler_facts.py` 的事实ID包含 `environmentHash`，该摘要包含 `receiptDigest`；`benchmark_runtime.py` 与工作台在模型之后重新生成候选编译，形成跨阶段身份差异。目标是修复接缝，不改变候选、行号或裁决门槛。

**拟改位置。** `compilation_runtime.py`、`risk_catalog.py`、`benchmark_runtime.py`、`audit_workbench.py`、`audit_run.py`、`audit_runner.py`、`tool_replay.py`及对应测试；若确需身份格式演进，再修改 `compiler_facts.py`，不预先扩大Java schema。

**推荐方案。** 优先复用已重验的发现编译输入、输出及binding收据，只为候选合约生成显式目标投影；环境证据仍绑定原收据，多合约各自重新核对AST／ABI入口、目标源码及合约身份。`manifestDigest`可以反映目标投影差异，`receiptDigest`保持同一来源。候选证据引用携带原收据／目录指针并随运行落盘，单样本、批量和历史重放使用同一接缝。

如原收据不可恢复，保持明确失败／UNKNOWN；不能去掉 `riskFactId` 或仅凭相同行号绑定。长期若需要跨独立收据的稳定操作ID，再以输入闭包、编译器、设置、重验输出、合约／入口／操作跨度建立有版本的语义身份与显式迁移桥；原收据摘要仍单独保留。禁止只按节点ID或源码SHA认定两个编译环境相等。

**验证与退出条件。**
