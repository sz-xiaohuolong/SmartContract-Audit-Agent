# R1-S6 批量对照工作台与数据扩充设计

状态：用户已明确要求清理无用 Milvus 集合、核对 D1 实验就绪程度、调研数据规模和改造批量对照页面。本小版本实施工程对照与研究设计；不把离线空假设报告当作 D1 效果。

## 范围与边界

1. 只删除已确认不被本机活动指针引用的旧 Milvus 集合；保留活动正式知识库及工程 MVP 集合，保留来源原件和历史报告。
2. 页面只允许已登记、谱系校验通过的独立验证目标批量选择 `DENSE`、`FIELD_FILTER`、`D1`。先展示固定知识快照、组合数、请求及输出上界，再开始运行。每项写入 JSONL，断点续跑不得自动重发可能已计费的请求。
3. 离线批量运行可验收工程链路。真实批量运行在完整提示输入 token 上界、真实 tokenizer 和费用上界未锁定前拒绝。单样本真实入口保持原有显式选择边界。
4. 页面展示各策略完成、失败、未知、入选证据与可用 usage；没有独立审核的目标—案例标签和可靠安全负例时，检测与检索效果指标保持空值，不报告“D1 提升”。
5. 文献调研以项目、漏洞事件、源码文件、向量片段等不同单位分别报告。数据扩充必须通过原件、修复对、标签和跨组隔离；不按向量条数凑规模。

## 验收

`mvn clean verify` 和 Python 全量离线测试通过；本机活动 Milvus 集合读回、HTTP 离线批量运行和逐样本报告回放单列证据。真实付费 API 调用次数为零。

## 2026-10-07 后续授权变更

用户明确取消真实批量的预算前置要求，并授权调用已配置的真实模型。因此第 3 条中的拒绝启动及验收中的零付费调用仅描述原始 S6 验收，不再作为当前入口限制。当前真实模式仍须由用户在页面显式选择并先预览计划；单项最多一次请求、零自动重试，逐项持久化。输入 token 与费用未精确锁定时继续显示空值，不将 UTF-8 字节数伪称为 token，也不据此宣称 D1 科研效果。
