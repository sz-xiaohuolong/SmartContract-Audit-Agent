# R3 优化计划：先验证差异知识的价值，再扩展检索与核验

R3 拟回答两个问题：把历史漏洞与修复解释成知识，是否让模型更准确地区分两侧；多路检索是否能找回原来遗漏的适用案例。计划先完善数据与评价，再逐步接入知识卡片和排序，最后根据证据决定是否扩展多次问答。

本文件于 2026-10-15 建立。**2026-10-16 用户明确要求按计划实施并运行一次真实 API 批量，首期工程范围据此进入实施。** 正式研究的数据准入仍单独判断；独立审核未齐时，只执行明确标记的工程探索，不宣称研究通过。R2 的真实修复缺口与历史验收保留。论据、论文版本及 Gemini 分析的修正见 [文献与源码分析](VUL_RAG_ANALYSIS.md)，当前实施决定见第 8 节。

## 2. 先解释一个预期使用场景

输入是一份待审合约。系统从知识划分中找到历史提现漏洞，卡片说明：“外部付款发生时，该用户的可提款余额仍可再次使用。”卡片附有原始漏洞、维护者补丁和适用前提，列出状态先更新、完整互斥锁等不同保护方式。

模型仅查看当前待审版本，定位付款、余额和相关入口，提出待核验候选。D2 用当前源码、编译收据和工具证据判断。若合约采用另一种有效防御，应核对该防御；若缺少跨入口或回调证据，结果仍为未知。目标的修复代码、真值标签和配对关系不会进入模型输入。

## 4. 每个切片怎样落地

### R3-00：补齐真实配对与公平比较的前提

沿用 [真实案例先导](../R2-20261010/attachments/REAL_CASE_PILOT.md)、`data/audit/` 的来源账本和 [d1_research_check.py](../../../../tools/experiment/d1_research_check.py)。先盘点能实际取得的漏洞、维护者补丁、报告、许可、依赖与编译范围，再决定可评估规模。

拟以 **20 对为先导收集目标**，并尽量平衡访问控制与重入；这不是“已经有 20 对”，也不是统计充分性保证。当前先导只有六项正式事件、四项待审，不能直接转成十组或二十组合格测试对。未达到准入规模时先提交数据缺口和描述性结果，不用合成补丁填满正式样本数。

每对分别保存漏洞存在与修复有效的依据，明确“只针对这一个漏洞”的标签范围。维护者合并补丁不自动证明所有漏洞均已消除。已用于调参的 RabbitHole、Atomic 等知识侧案例继续留在开发侧，不重新命名为独立测试；其他验证侧案例一旦用于选卡片、调排序或改提示，也必须退出独立测试。

按项目、漏洞事件、补丁祖先和相似源码谱系分组后再划分知识、开发与测试。记录作者／工具版本、原始字节摘要、审核人和争议裁决。独立审核人不得只复述生成模型或卡片的结论；同一 Agent 再读一遍不计独立审核。无法取得独立审核时，研究状态保持尚未验证。

**通过条件：** 清单中每个主评估对的两侧、来源、标签范围、谱系和划分完整；测试目标及其同事件补丁不在知识索引中。编译失败、原件缺失和标签争议在冻结前按统一准入规则处理并报告数量；冻结后的失败继续保留，不临时挑选成功样本。

### R3-01：卡片附着于原件，保留安全相关语义

复用 [check_templates.py](../../../../tools/experiment/check_templates.py) 的来源校验与保守绑定，并沿用 [d1_consumption.py](../../../../tools/experiment/d1_consumption.py) 的原始代码对。新增的卡片是附加描述，即与原件分开保存、通过身份关联的文件；旧快照及历史候选不覆盖。

| 字段组 | 最少内容与约束 |
|---|---|
| 身份与来源 | 卡片及 schema 版本、pair／事件／谱系 ID、原件和报告 SHA-256、补丁提交、许可与划分、原源码行段指针 |
| 功能与行为 | 来源支持的功能目的、可见操作与次序、信息缺口；每条陈述可定位依据 |
| 诱因与影响 | 调用者、资源键、状态版本、触发前提与后果；无法绑定的值保持空或未知 |
| 保护义务 | 要阻断什么攻击路径；把历史补丁采用的手段与其他经核对的等效手段分开 |
| 适用与局限 | 需要哪些源码、入口、外部依赖和工具证据；已知不适用情况与反例 |
| 审核与生成 | 人工或模型生成方式、模型／提示身份及实际成本、来源审核与语义审核分别记录 |

模型呈现只取已审核的机制说明、必要前提与历史来源引用；目标真值、测试划分和目标配对身份留在评价侧。检索对的修复标签属于历史知识，可说明其来源；不得借此泄漏测试目标的标签。

局部变量名可用稳定映射简化，但保留 `msg.sender/tx.origin`、`call/delegatecall`、映射键、存储位置、调用顺序和资源归属等安全含义。卡片不能把“任意授权检查”写成“只有 onlyOwner 才安全”，也不能把无法解析的业务目的编出来。

**通过条件：** 首批每张卡片均能回读匹配原件；独立审核逐项核对触发条件与修复效果；坏摘要、错配资源、来源越界及审核缺失会被拦截。报告分别列来源通过数、语义审核通过数和未通过原因。初期可人工编写，不先申请全量模型抽取。

### R3-02：先独立召回，再冻结并集排序

主要接入 [recall.py](../../../../tools/experiment/recall.py)、[benchmark_runtime.py](../../../../tools/experiment/benchmark_runtime.py)、[formal_recall.py](../../../../tools/experiment/formal_recall.py)。Python 是本批实验编排入口；只有实际经过 Java 检索时才同步对应策略，避免只改 `HybridRetriever` 却没有影响运行路径。

首期提议采用现有密集向量召回，加三路本地 BM25：代码、已审核目的描述、可见行为。查询目的若无法从现有证据确定则标缺失；AST 行为摘要标明范围与限制。若后续采用模型生成目的和行为，作为单独协议版本核算调用，不静默混入。

每路对完整知识划分独立检索，然后归并为完整 pair，形成共同并集。拟沿用向量前 80 项、各 BM25 前 10 项作为开发初值；这些值在开发集上核对后冻结，不在测试集选优。片段路归并时取同一 pair 成员的最好名次，再生成连续的案例名次；最终按事件去重，每事件最多选一对。每个成员保存各路名次、原分、缺失标志、来源和配对完整性。

排序对照使用现有冻结代码向量，pair 的向量分数取两侧成员的最高分；BM25 独有成员也须用同一查询向量补算分数，不能把“向量路未进前 80”写成“没有向量”。向量确实缺失时按预登记规则对共同池处理并报告，不只从一个排序臂删除。首期不新增卡片嵌入；如需更换嵌入表示，另列因素、快照与成本。

融合默认候选方案为论文式 `Σ 1/rank`，排名从 1 开始、未召回贡献 0、同分按稳定知识 ID 排序。常数 60 的融合和作者当前加权排名如需比较，登记为不同策略；不混用名称，也不让缺失路获得虚假名次。保留分数与各路返回集合，以便复算。

**通过条件：** 夹具中仅词法路能命中的案例确实进入并集；缺失路、重复事件、并列与不同返回长度均确定可复算；补齐不会引入目标事件或破坏预算。未审核完整知识库时，只报告候选池内召回率，不能声称全库召回提升。

### R3-03：同一案例的代码与卡片可以切换

在 [HypothesisService.java](../../../../audit-mvp/src/main/java/com/xhl/audit/HypothesisService.java) 的现有候选生成与引用校验上增加显式表达方式；通过 Python 运行配置传入。保留原 D1 路径作为对照，卡片缺失或预算不够时记录拒绝原因，不能静默换回代码后仍标记“卡片实验”。

表达对照固定选中案例 ID 与顺序，代码臂使用漏洞／修复两侧，卡片臂使用同一历史案例的审核说明。首期每个目标最多两对，卡片最多两张；这是共同上限，不保证每个目标都能装满。记录实际数量、全部呈现文本 SHA、被拒项和源代码范围。

预算同时登记目标源码、系统提示、任务指令、参考材料、输出上限和完整请求身份。沿用 4096 字节参考材料上限作工程兼容限制，但不把它称为精确 token 公平。给代码与卡片预先分配相同的参考 token 上限，并记录实际 token 使用，不用无关文字填充较短表达；所有差异如实呈现。

**通过条件：** 假模型收到的文本与消费回执一致；目标标签和补丁不进入请求；超预算整项拒绝；无模型、无卡片、坏 schema 和格式失败均保持明确状态。若端点没有可验证的完整提示计数方式，标记预算公平尚未验证，不发布严格公平的增益结论。

### R3-04：把表达、排序与证明分开评价

扩展 [eval_ragas.py](../../../../tools/experiment/eval_ragas.py) 和既有计分入口，不新增第二套结果平台。先完成人工相关性，后续若使用 Ragas，只作语义诊断并另计成本；不能把卡片或模型回答当独立参考答案。

新卡片、索引、查询和候选并集必须生成新的 schema／快照／pool 身份。现有比较要求来源、快照与 pool 一致；需要通过显式适配验证两种表达的原件、选择 ID 和顺序对应，而不是伪造旧 `poolHash` 或绕过校验。保留历史格式只读回放测试。

排序同时保存“案例级”和“片段级”的单位：一对代码有两片段，一张卡片是一案例的表达，不能用相同的 k 冒充相同信息量。表达对照按同案例评价；既有 P@k 等片段结果继续按原定义保存。无检索的 Vanilla 不计算检索排名分数。

**通过条件：** 小型手算例可复算配对准确率及 P@k、池内 Recall、MRR、nDCG；坏身份拒绝比较，未审核和无相关项不自动给零分或满分；所有新字段保留空值含义。具体正式研究设计见第 5 节。

### R3-05：让卡片提出问题，让独立证据给出结论

沿用 [d2_verify.py](../../../../tools/experiment/d2_verify.py)、[compiled_d2.py](../../../../tools/experiment/compiled_d2.py)、[reentrancy_proofs.py](../../../../tools/experiment/reentrancy_proofs.py) 和 R2 真实修复检查。卡片可以携带待检查的操作、资源和保护义务；这些值都须重新绑定当前源码，不能继承历史案例的路径或真值。

回归矩阵至少覆盖：原始漏洞、历史补丁、当前语义范围内的等效修复、表面相似但无效的保护、证据不完整。等效修复可选状态先更新与完整互斥锁；近似错误修复包括锁只覆盖一个入口、检查错调用者或余额键、失败后异常状态。人工构造变体只用于机制回归，不冒充真实研究配对。

访问控制检查权限从哪里来、是否检查正确主体、初始化与继承是否留有绕过；重入检查同资源、状态版本、回调入口和正常提交。缺少有效编译、动态调用语义或跨合约闭包时仍为未知，不以名称匹配或一个支配节点代替全部义务。

**通过条件：** 未命中历史修复不能直接支持漏洞，出现保护名字不能直接反驳；缺工具与格式失败仍未知；既有结果若改变，逐项给出新增或修正的独立证据。固定 163 候选在新规则下另建派生重放，不覆盖原 82／0／81；新生成候选另统计，不宣称同分母下降。R2 真修复仍未通过时，本切片可完成回归设施，但不得声称该双向验收已完成。

### R3-06：先做离线准入，再运行研究条件

复用 [synapse_protocol.py](../../../../tools/experiment/synapse_protocol.py) 的冻结、预算、执行锁与回执设施。先用假模型走通全部请求、失败、恢复和统计，再确认实际模型配置。冻结代码及 JAR、依赖、快照、卡片、查询、目标、提示与协议摘要；运行中变化即停止受影响单元，不能跨二进制阶段后合称单身份实验。

采集授权必须写明确切模型、计费端点、请求数、重试、输入／输出预算和停止条件。2026-10-14 的历史授权已消费；2026-10-16 用户另行授权本轮一次真实批量，具体边界见第 8 节。真实凭证继续使用现有忽略配置，测试不依赖实际端点。

**通过条件：** 所有计划单元都有成功、失败或未运行记录；实际消费与冻结身份一致；usage 缺失为 null；预算超限停止，不换端点续跑。运行报告同时保留不支持假设或样本不足的结论。

### R3-07：有证据需要时，单独试验顺序两问

若首期显示卡片适用但单次生成仍难以绑定事实，可增加“诱因是否存在”“是否有任何适用的有效防御”两问。第二问不限定历史补丁写法，两问均允许证据不足。记录检索顺序、每次提示、回答、失败和停止原因；未遍历、未命中或模型否定不直接成为 D2 结论。

对照固定卡片、选择结果与总预算。若两问使用更多调用或 token，只报告相应成本下的结果，不能与单次生成混为同预算提升。早停策略需单列，避免把第一张卡片的修复回答当成排除所有漏洞。

## 5. 研究怎样区分不同因素

### 5.1 两阶段、五个条件

先冻结合格测试对及其每一侧的输入。两侧始终分别运行，模型不知道它们配对。以下为首期拟定条件，具体模型与预算待调用前确定。

| 阶段与条件 | 固定什么 | 改变什么 | 回答的问题 |
|---|---|---|---|
| 表达 A：Vanilla | 同一目标、生成模型与目标源码 | 不提供检索上下文 | 不加知识的发现基线 |
| 表达 B：原 D1 代码对 | 冻结选中案例及顺序 | 原漏洞／修复代码表达 | 配对代码参考的结果 |
| 表达 C：同案例卡片 | 与 B 相同的案例及顺序 | 审核后的知识表达 | 表达变化是否有帮助 |
| 排序 D：dense@union | 新冻结多路并集、固定卡片与预算 | 对并集按向量相似度排序 | 扩展池内的向量排序对照 |
| 排序 E：fusion@union | 与 D 相同的并集、卡片与预算 | 按预登记多路名次融合 | 融合排序本身是否有帮助 |

B 与 C 的选择结果在比较前冻结，不能 C 用更好的知识、B 用旧噪声后称为表达消融。D 与 E 共同使用新并集；`dense@union` 不是历史 R2 原样 DENSE。扩展候选来源的影响先用离线池覆盖说明，若要研究其下游因果增益，另增单独条件与预算，不从 D／E 差异推断。

若某案例无法在共同预算下完整呈现，按预先规则对 B／C 同时处理并记录，不在看到模型成绩后删目标。短卡片与长代码的实际 token 不必相等，但共同上限、可消费信息、实际花费和拒绝情况必须公开。

### 5.2 指标与分母

| 层次 | 主报告内容 | 不得代替什么 |
|---|---|---|
| 数据与运行 | 准入／排除数、漏洞与修复数、项目数、成功／失败／未运行、调用与延迟 | 不能只展示成功子集 |
| 检索 | 独立人工相关性、P@k、池内 Recall、MRR、nDCG、事件覆盖及各路增量 | 池内召回不等于全库召回；相关性不等于漏洞真值 |
| 模型发现 | **配对准确率为主**；另报两侧正确率、修复侧误报、漏洞侧漏报、F1 与定位质量 | 格式有效不等于判断正确，F1 不替代修复辨别 |
| D2 核验 | 支持／反驳／未知、证据覆盖、真实修复双向结果、错误接受／错误拒绝（有独立候选标签时） | 支持比例不等于准确率；模型判断不等于证明 |
| 辅助诊断 | 如启用，Ragas 分数与人工校准 | 不替代主指标或独立标签 |

配对准确率分母是冻结后的全部 N 对：只有漏洞侧正确判漏洞、修复侧正确排除目标漏洞，才计 1。任何一侧失败、未运行或弃权，该对主指标不计成功；另外报告原因和有效覆盖。不得用“共同成功子集”替换主分母。F1 对有效二分类输出单列覆盖与完整计划数，失败不伪造为安全；可另列共同有效子集敏感性分析。

发现主指标在 D2 过滤前统计。若报告端到端效果，D2 反驳仅在候选与目标漏洞明确绑定、证据覆盖充分时计入；未知保留为未知。独立候选标签不足时，错误接受／错误拒绝保持未定义，不能直接拿目标级标签补齐。

比较以同一对、同一重复为配对单位，按项目／事件聚类给出 95% 差值区间，并报告两类漏洞和修复方式的分层结果。重复采样不增加独立项目数。正式增益主张至少要求预登记主比较 C−B、E−D 的差值区间下界大于 0，并同时报告修复侧误报差的区间；不能排除误报恶化时，不宣称整体可靠性改善。R3-00 在看测试结果前冻结重采样、重复结果聚合及两个主比较的多重比较处理方法；独立项目不足时只给描述性结果。小先导不把显著性作为工程接通条件，也不预设“至少提升 20%”。多次调参、次要指标与可选因素单独注明。

### 5.3 成本怎样提前封顶

设合格配对数为 N、每条件重复数为 R，则每条件目标单元数 `S = 2 × N × R`。五个条件的主生成上限为 `5S` 次；例如 N=20、R=1 时最多 200 次主生成。这只是算术预算，当前没有合格 20 对或 200 次调用授权。

| 额外环节 | 单独计数方式 |
|---|---|
| 离线卡片抽取 | 实际抽取单元 × 每单元调用数；人工编写则为零模型调用 |
| 查询目的／行为摘要 | 若每源码 q 次、各条件共享，则为 `2Nq`；随机重生成或重复 R 次时据实增加 |
| 可选逐条两问 | 每目标最多 K 张卡片，额外上限 `2KS` 次；不能隐藏在原来的单次生成数内 |
| 语义评判与重试 | 按评判指标内部调用和实际尝试分别登记；默认不自动重试，若允许则预先封顶 |
| 工具执行 | 编译、Slither、本机 EVM 的次数、时长与身份单独记录 |

最终授权表还须写每类调用的完整提示与输出 token 上限，总量按各类“次数 × 上限”求和。单价或计费依据不明时金额留空并登记 token／请求上限，不猜测免费或沿用旧价格。未知 usage 不补零。
