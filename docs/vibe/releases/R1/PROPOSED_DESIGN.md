## D1 工程设计与语义边界

日期：2026-09-22。落实用户已授权的 S2 工程需求；不表示论文创新效果已经成立。

### 实际调用链

`program_facts.py → PythonFactsExtractor → RetrievalStrategy → EvidenceBundle`。

另一路：`S1b 完整快照 → recall.py（本地余弦或 Milvus）→ 绑定目标 sourceHash 的 CandidatePool`。Java 检索接口只消费导出的知识候选与程序事实，不读取审核清单中的目标标签。目标源码必须匹配候选池绑定，召回导出前确认目标属于快照全量清单的非 knowledge 划分。源代码路径与 CLI 参数不会触发模型调用。

### 事实语义

事实提供器使用标准库词法与括号结构分析，记录合约状态变量、函数作用域、修饰器名称、CHECK/WRITE/CALL、源码行号及展开后的相对顺序。源码 SHA-256 和作用域内事实 ID 使引用可追溯；同一行重载函数使用独立作用域编号。

- `CHECK`：require/assert 中受支持的等值比较。它是检查的事实，不自动等于权限验证成功。
- `WRITE`：受支持的直接状态写语句；不推断具体数值是否完成资金扣减。
- `CALL`：受支持的低级外部调用、send/transfer；主体是源码中的接收方表达式。
- 无参数、单占位符的局部修饰器按嵌套顺序展开；仅有 onlyOwner 名称而无定义时保持未知。

分支、循环、继承、汇编、未知调用、内存/存储别名、复合赋值未支持形式、元组赋值、参数/局部遮蔽等产生 PARTIAL。这些作用域的条件判断返回 UNKNOWN。赋值右侧含外部调用也降级，避免把左值出现位置误当实际写入顺序。短路运算、多维索引、局部赋值、单语句多重赋值以及作为下标的状态变量发生写入，也降级为 PARTIAL；当前不追踪这些表达式的数据流。结构损坏返回 FAILED，不能解释成没有防护。

这不是完整 Solidity 解析器、编译器、CFG 或跨函数分析器。即使状态为 COMPLETE，也仅表示本提供器的受限结构处理完成，不证明源码能编译、可达性或保护有效性；正式研究数据还必须有独立编译与语义审核。

### 角色与条件

Target 明确给出 mechanism、riskFactId 和角色：actor 必须为当前调用者 `msg.sender`；resource 对应当前风险操作资源；authority 由调用方明确指定为权限状态槽，程序不从 `owner` 等名称猜测合法主体。状态写目标必须与 resource 一致。

两种初始条件：

| 谓词 | 检查对象 |
|---|---|
| CHECK_BEFORE | 同作用域内，在风险之前检查指定主体与指定权限槽相等 |
| STATE_WRITE_BEFORE | 同作用域内，在外部调用之前写入指定状态资源 |

条件使用 `$actor/$resource/$authority` 显式绑定。输出 SUPPORTED/CONTRADICTED/UNKNOWN，包含具体事实引用与原因。不同作用域、错误主体、明显不同的状态资源、检查过晚均不能提供前置支持；同一映射的不同动态下标不能直接认定资源不同，保留 UNKNOWN。等式正反写法使用相同的主体与权限槽别名规则。检查后同根权限槽被写入（包括可能别名的其他下标）或发生外部调用时，旧检查失效，保留 UNKNOWN。

STATE_WRITE_BEFORE 仅表达顺序，不说明更新值足以防止重入；案例适用性不是漏洞裁决。未知或矛盾案例可以出现在传统检索对照中，但 D1 不将其用作直接支持。

### 配对和强对照

CandidatePool 固定 snapshotId、sourceHash 和完整候选块；每个候选包含来源、已审核标识、配对 ID、机制、风险种类、角色和条件。候选池摘要保存进每份输出。

- Dense：按向量相似度排序。
- Hybrid：同一候选池按 cosine + 词集合 Jaccard 排序；这是明确固定的先导规则，不声称训练得到最优权重。
- 普通正反例：同机制分别选高分漏洞例和防御例，不使用条件过滤或配对差异。
- D1：只接受同审核配对、同机制、同风险种类且条件有差异的两侧；当前条件匹配的一侧作为 SUPPORT，另一侧作为 CONTRAST。按条件覆盖数、向量分数和稳定 ID 排序；去掉重复案例块、相同正文和无新增条件覆盖的配对。

所有策略使用相同 `Budget(maxBytes,maxCases)`。预算精确覆盖返回的 `context` UTF-8 字节（包含案例标识、角色和正文），不把无固定 tokenizer 的估算冒充模型 token。证据解释单独返回，不能在后续模型提示中免费追加解释或额外案例；正式模型实验必须冻结 tokenizer 与整个提示预算。

输出记录所有候选的逐条件评估，包括未被选择的 UNKNOWN/CONTRADICTED 项。没有有效防御案例、支持侧未知或预算不足时输出缺口，不拼造案例。案例 REVIEWED 与 pairId 是审核输入要求，程序不能替代对补丁真实有效性的人工审核。

### Milvus

本地镜像 `milvusdb/milvus:v2.6.4` 已实际验证。`MilvusRestIndex` 用标准库 REST 请求实现独立集合创建、完整读回和搜索，复用 S1b 的快照激活门禁；只允许 loopback URL 和 `s1b_` 随机集合，不修改旧集合或别名。凭证仅从 `MILVUS_TOKEN` 环境读取，HTTP 错误不输出服务端原文。

远端候选 ID、重复项、返回数量和 cosine 分数均对照本地快照核验，失败不回退为模型推测。当前分页读取使用 offset，超出服务器窗口会显式失败，未声称适用于无限规模知识库。

接口参考：[Milvus 向量搜索](https://milvus.io/docs/single-vector-search.md)。启动差异依据 [v2.6.4 配置源码](https://github.com/milvus-io/milvus/blob/v2.6.4/pkg/util/paramtable/service_param.go)：本地镜像须在进程初始化前设置 `DEPLOY_MODE=STANDALONE` 才能启用嵌入式 etcd。

## R1-S3 技术与实验设计草案

状态：首个工程切片已实施；真实研究与锁定测试流程仍待审核。以 [SPEC](SPEC.md#s3-spec) 和[第二轮查新](../../../../thesis/D1_D2第二轮查新与立题裁决_20260924.md)为约束，实施时只作经过源码核验的局部调整。

### 数据流与信任边界

公开来源登记 → 原件与哈希 → 事件/项目/补丁/克隆关联图 → 分组划分 → 独立条件与真值审核 → knowledge 快照 → 固定候选池 → S2 四策略与简单字段过滤 → 离线适用性评价 → 小批模型下游先导。

所有衍生材料继承源样本和关联组；同一项目不同函数或修复前后不能跨 knowledge/test。保留原文件、原报告、提取过程和拒收理由。原始来源由独立证据支撑时才可标真假；没有报告的代码不能自动称安全。

S2 当前事实提供器对分支、跨函数、别名、继承等返回部分或未知。先导标签记录其失败边界。扩展解析能力须先证明相对“简单字段过滤＋人工标签”的独立价值，不能把 UNKNOWN 当保护不存在。建议先使用现有 Python/Java 契约，必要时接有版本锁定的 solc/Slither 作为事实来源，并保留来源冲突。

### D1 比较

对每个风险操作固定 sourceHash、机制、知识快照、候选 pool、embedding/词法索引与下游模型配置。检索结果实际传给 LLM 的完整提示（系统、源码、问题、证据、工具摘要及格式开销）以真实 tokenizer 计数；检索正文 UTF-8 字节预算仅作现有工程检查，不能冒充 token 公平。无模型时先比较相同证据 token 上限的检索层指标。建议实现一条“简单条件字段过滤＋原排序”强基线，避免只与弱 Dense 比较。

相关性标签按目标—案例逐对审核：0 不适用；1 部分有用但关键条件未知；2 有判别价值；3 直接可核查并填补关键证据。支持与反驳价值分别标注，防御例不默认相关。主比较为 D1 对最强非 D1 基线的项目级配对差，分层报告重入/访问控制；小样本只报告计数与区间。合成最小差异只作压力测试。

### D2 预研边界

固定候选含来源发现器、目标位置、声称攻击路径、前提、正/负真值依据。保护覆盖义务可暂表示：主体一致、资源一致、保护在风险前、覆盖所有相关可达入口、状态读写版本有效、无已知绕过。每项记录支持/反驳/未知与代码位置；该表本身不是创新，下一阶段先用它定位已有过滤器的错误。

基线：未核验、guard 存在性、具体防护行、路径可行性规则、等预算单模型 Critic。若做论文方法近似复现，标清差异，不用作者自报数值作为同集结果。未知不当作安全；报告错误接受、错误拒绝、弃权/覆盖率和成本曲线。完整“义务驱动补查”仍是 G3 后任务。

### 预算与终止

火山套餐到期日为 2026-10-18 23:59，目标 deepseek-v4.1-flash。先给出模型/端点/温度/提示版本、样本数×策略×重复×阶段×重试的调用上界，再显式选择真实运行。测试不得依赖真实 API、Milvus 或工具环境。失败、超时、解析错误均保持独立状态，usage 缺失为 null。锁定测试不参与调参。

## R1-S4 目标设计：正式知识库驱动的单样本审计链路

状态：`APPROVED`，2026-10-05。本文描述**拟实现**架构；用户已批准函数级工程试跑的追加边界，现有架构仍以代码和 `docs/vibe/TECH_DESIGN.md` 为准。对应需求见 [SPEC](SPEC.md#s4-spec)，方案选择见 [CHANGE_PROPOSAL](decisions/S4_CHANGE_PROPOSAL.md)。

### 总体结构

沿用方案 A：`tools/experiment/` 负责本机目标登记、谱系、快照读取、运行编排、报告和 HTTP；`audit-mvp` 保持 Java 21 / Spring AI 2.0.1，负责 D1 检索、严格模型输出及工具解析。Python 与 Java 通过版本化 JSON 和受控子进程通信；不增加第二个独立服务或数据库表。页面是本机 HTTP 的只读展示与显式运行入口。

```text
已登记开发目标 ──源码摘要／组隔离──┐
                                    ├─同版 BGE 编码─正式 Milvus 召回─Java D1─证据包
激活 s1b_ 快照 ──完整性读回──────────┘                              │
                                                              结构化模型假设（至多一请求）
                                                                      │
                                                      Slither／可选 Mythril 工具证据
                                                                      │
                                                       D2 保护义务初版判断
                                                                      │
                                               持久化 JSONL／汇总─本机页面回看
```

### 边界和接口

#### 目标登记与检索

目标注册器读取固定首批分配与 intake，重算源码 SHA-256，并用首批完整 ledger 和正式知识快照 manifest 检查项目、事件、补丁对、精确重复及已发现近克隆边。仅 `development`、源码核验通过、无知识侧关联的样本可运行。`AC-ASE-006/009` 可进行整份源码单次模型工程试跑，但事实提取器没有与正式访问控制知识对匹配的调用风险事实，D1 返回明确缺口；不得把空证据包说成成功条件绑定。`RE-SCRUBD-002` 因源码尺寸超限显示阻塞原因。当前没有正式准入的开发真值，所有试跑结果带 `researchEligible=false`。

`RE-SCRUBD-001` 的 `matchOrderWithReserve` 作为唯一函数级工程入口：用原始完整源码提取事实、定位第 608 行调用和运行工具；从完整源码按函数声明与配对花括号截取片段，保留原始行号及完整源码／片段 SHA-256，模型提示明确“只分析该函数，其他调用上下文未知”。若源码摘要、函数边界或提示字节预算有任一不符则拒绝运行。函数内部含分支，D1 条件绑定为 `UNKNOWN` 时仍应展示召回候选与未选原因；不能把空 D1 上下文补成模拟证据或完整合约结论。

原有 `recall_pool` 对目标必须出现在正式快照 manifest 的要求保持不变，以保护既有研究入口。新增**工程目标适配器**在外部完整 ledger 上校验目标后，生成仅含目标源码摘要、同一正式快照 ID 和同版 embedding 的检索请求；适配器不得写入快照或改变 `recall_pool` 的研究语义。Milvus 返回每条候选须经本地快照 ID、向量分数、文档 ID 和内容再校验；异常即拒绝。Java D1 输出 `facts`、候选绑定、选中上下文及未知理由。对于多风险事实，只选择注册清单明示的单个工程检查点；该检查点是**页面试跑范围**，不可流入研究标签或正式实验的自动检索。研究版完整扫描留给后续需求。

#### 模型、工具与 D2

新增版本化 `HypothesisReply`：顶层 `schemaVersion="2"`、`hypotheses` 数组（0–3 项）；每项字段固定为 `vulnerabilityType`（`ACCESS_CONTROL` 或 `REENTRANCY`）、`contract`、`function`、`riskLine`（正整数）、`riskOperation`、`reason` 和 `evidenceIds`。模型可报告“未发现”，用空数组表示；不得直接输出“安全”。后端核对 JSON 无多余字段、风险行存在于目标源码、类别与单样本注册机制一致、证据 ID 出现在 D1 包中。无效结构、输出截断和空正文各自保留错误分类。现有 S0 三字段 `AuditResult` 与历史报告不修改；新模式使用独立命令入口和独立响应类型。

工具适配层复用 `ToolAnalyzer`／`ProcessRunner`。Slither 为默认本机证据源，可配置关闭或缺失；Mythril 为显式可选源。每个结果保存引擎、状态、工具版本、源位置／告警及耗时；只允许固定可执行文件配置，不接受浏览器路径。没有工具时 D2 仍可读取轻量程序事实，但缺证据的义务只能 `UNKNOWN`。工具失败与模型失败分别计数，零告警不改变模型为安全。

D2 初版以模型假设为**待核查主张**，以“保护是否覆盖该风险”为六项义务：主体一致、资源一致、检查先于风险操作、相关入口覆盖、状态版本正确、无已知绕过。每项带 `SUPPORTED/REFUTED/UNKNOWN`、源码行和工具／事实引用。只有存在可核查风险路径且至少一项必要保护被具体证据反驳时，漏洞主张可标 `SUPPORTED`；只有所有必要保护均有可核查支持且风险路径被阻断时，主张才可标 `REFUTED`；其余为 `UNKNOWN`。轻量事实对继承、分支、别名等返回 `PARTIAL/UNKNOWN` 时不得升格为证明。D2 不调用模型，不把假设判断当独立研究真值。若模型阶段失败，D2 不生成肯定或安全判断，最终 `UNRESOLVED`。

#### 持久化与页面

新增 `.local/audit-runs/<runId>/`，其中 `plan.json` 固定样本、源码／分配／快照／catalog／模型／提示版本和请求上界摘要；`events.jsonl` 逐阶段记录启动、完成、失败且逐行同步；`sample.jsonl` 最多一条终态样本记录；`result.json` 是原子发布的页面视图，包含 `schemaVersion="1"`、阶段状态、证据引用、用量及失败／UNKNOWN 分母。完整模型原文可按现有安全规则仅留本机诊断文件，不经 HTTP 暴露。旧 `.local/mvp-runs/` 保留只读，绝不自动迁移或回填。

运行器只对从未有启动标记的运行发起模型调用。若进程在发起后中断，恢复逻辑发布 `FAILED/UNRESOLVED` 的可读记录并要求显式新运行；不得猜测供应商是否已经计费，也不得自动重试。历史读取和 JSONL 下载只访问磁盘。HTTP 新路由只允许白名单样本 ID 和 `mode=offline|real`，拒绝额外字段、超大体、非本机 Host／Origin，并使用单写者锁避免并发付费。页面用文本节点显示来自源码和模型的数据，避免把检索文本渲染为 HTML。

### 验证、上线和回退

验证矩阵覆盖：正式／演示集合混淆、指针篡改、Milvus 返回不完整或错分、目标源码改变或与知识同组、事实 `UNKNOWN`、模型缺字段／多字段／截断、Slither 缺失／超时／损坏输出、D2 六项证据不足、中断后恢复、历史读取零调用、并发与跨源请求拒绝。全部默认用本地假索引、HTTP 和子进程夹具；根 Maven 与 Python unittest 为必跑检查。真正的 Milvus、Slither、Mythril 和 DeepSeek 冒烟均须单独记录，不参与默认自动测试。

按垂直步骤交付：①正式快照与 D1 页面预览；②模型假设与工具证据；③D2、报告和回放；④整链离线人工验收。每步保持旧 `/mvp.html` 可用；新路由可单独停用，新文件只写 Git 忽略的独立目录，正式 Milvus 集合只读。只有实际完成且有新鲜测试证据的小版本才按仓库约定提交并同步；研究验证状态不因工程完成改变。

## 数百条候选知识的探索性 D1 对照

用户目标：先用已经落到 Milvus 的 742 条候选向量，配合 SmartBugs Curated 或 SolidiFI 的独立目标，在页面查看 D1 与普通向量召回、简单字段过滤的批量差异，再逐案完善标签与真实修复证据。

### 冻结的实验含义

本轮另建“探索性候选知识”入口，复用现有 `r1pending_` 集合，**不切换正式 `s1b_` 指针**。AutoMESC 的 300 组改动前后片段标成“暂定原版／暂定改版”，只在有可复核的句法变化时参加 D1 配对；FORGE 的 142 条单侧报告源码只参加向量候选召回，不能伪造防御对应项。全部条目维持 `PENDING`，页面、逐样本记录和报告都标 `researchEligible=false`。

第一轮查询目标使用本地 SmartBugs Curated 文档中的访问控制与重入源码，排除与候选知识完全重复、项目同源或近克隆的目标；这些目标是**公开示例的探索性测试层**，不能充作锁定测试或真实补丁负例。SolidiFI 为注入型数据，后续单列合成／人工变体层，不与真实目标混算。

### 算法与边界

- 每次查询固定候选集合身份、BGE 模型修订和同一 Milvus top-K 候选池；Java 原有 D1、Dense、字段过滤在相同池及 UTF-8 上下文硬限运行。字节上限仍不称为完整 token 公平。
- 新 `exploratory-1` 候选池只允许 `reviewed=false`；正式 `1` 候选池仍要求 `reviewed=true`。Java 在输出中保留候选池版本。D1 对探索性配对只作**句法适用性**选择，不证明原版有漏洞或改版安全。
- `NON_REENTRANT` 只表示目标函数有明确 `nonReentrant` 修饰器；缺少修饰器不能证明缺少其他重入保护。遇到不完整解析、别名或跨函数风险保持 `UNKNOWN`。
- 批量报告逐样本保存候选池摘要、三策略入选案例、失败与 `UNKNOWN`；没有目标—案例人工适用性标签时 Recall@K、nDCG 与审计准确率为 `null`。页面必须能辨别探索性与正式报告。

### 可验收的首步

本阶段先完成离线确定性的检索层试跑：742 条候选通过本地正文、向量、元数据和 Milvus 完整读回；固定一批隔离目标后输出逐样本 JSONL、三策略入选量与失败分母，并能在本机页面查看。真实模型审计批量入口沿用已有显式配置和逐项计划，但仅在探索性目标登记、提示边界与报告契约完成后开放。**检索层试跑不等于 D1 提高合约审计准确率**。
