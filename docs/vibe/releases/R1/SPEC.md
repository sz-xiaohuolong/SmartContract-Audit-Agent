## S0 有效需求：可信运行底座与多 Provider 接入

日期：2026-09-19；Requirement Status：FROZEN；Open Questions：None。
批准依据：用户明确认可已展示的分阶段实施方案，要求正式编码，并明确授权升级依赖、切换火山引擎和兼容多 provider。
本切片落实此前 S0；D1/D2、知识迁移、大规模付费实验继续按后续阶段推进，不因本次编码授权冻结论文创新。

- S0-01：使用核验过的最新稳定 Spring AI / 兼容 Spring Boot；旧 M6 实验路径隔离保留，不强行将旧错误口径混入新版。
- S0-02：多命名 provider 配置，可指定默认 provider，火山 Agent Plan 示例为默认；端点和 model 可配置，密钥仅环境变量。未配置真实凭证也能离线测试。
- S0-03：模型返回原文、usage（缺失为 null）、供应商、模型、耗时；结构错误、空返回、鉴权失败不转为安全。
- S0-04：最小审计 CLI 接受本地源码，单次调用后严格解析结果，返回运行状态与漏洞存在判断；不把无发现写成证明安全。
- S0-05：工具进程从启动计时，独立排空 stdout/stderr，限制留存输出，超时清理进程，结构化返回状态；Slither/Mythril 可配置可执行路径。
- S0-06：默认 mvn test 不发外网请求、不启动 Milvus、不调用真实模型/工具；本地 HTTP 夹具验证实际 Spring AI 路径、鉴权、模型切换、usage、HTTP 错误。
- S0-07：每次 CLI 输出包含 sourceHash、执行状态、结果、usage 与时间；无效输入/模型失败退出非零；不在控制台打印密钥。

付费额度未知不影响以上软件行为：默认不自动运行真实请求，用户显式运行时单次调用，无批量调度。本切片不引入云端新服务、不迁移数据库、不推送发布。

## S1 数据与实验基础：有效需求与当前切片

日期：2026-09-20。用户已批准分阶段实施并要求继续；范围沿用 S1，不自行冻结论文方法或正式测试数据。
Requirement Status：FROZEN（工程行为）；Open Questions：None（当前切片）。

S1a 范围：只读数据清单和离线类型评估器。

- 扫描 Solidity 文件，生成可复查的路径、字节哈希、稳定 ID、完全重复组；不移动、删除或修改源码。
- 不从目录自动推断真值。清单的标签、项目谱系和正式划分保持待审核；完全重复组不冒充项目/克隆全覆盖。
- 离线评估严格接收审核标签与预测结果；拒绝重复样本、未知样本、未知类型及无效状态。
- 错误类型同时贡献预测类 FP 和真实类 FN；类型预测按集合计，实例级重复惩罚由后续定位评估承担。
- 执行失败和缺结果保留在计划样本分母；正样本未检出计入端到端 FN，但负样本失败不能计为正确完成或 TN。
- 指标包含类别 TP/FP/FN、微平均与预定义类别宏平均 F1、完成率、失败/缺失率、负例误报率和正确且完成率；零分母为 null。
- 评估只读取结果，不调用模型。不得把未经审核的旧目录标签输出为正式研究成绩。

S1b 范围：知识快照完整性与激活、分组划分校验、持久记录及 checkpoint/resume/replay。用户于 2026-09-21 明确要求继续实施；实现与验收状态见 IMPLEMENTATION_PLAN.md 和 VERIFICATION.md。正式标签及数据比例另行审核，不妨碍工具开发。

指标细化：预定义全类别 macro_f1 在任何类别 F1 无定义时为 null；仅有定义类别平均使用独立名称 macro_f1_defined_only 并列出分母类别，不替代主指标。

## S2：D1 条件感知对比检索工程规格

日期：2026-09-21。Requirement Status：FROZEN（本轮工程范围）；Open Questions：None（工程行为）。用户本轮明确要求按 R0 S2 规划实现事实提取、D1、独立对照与离线验证，并授权使用本地 Milvus。正式数据配对与研究效果不随工程授权自动成立。

### 范围与验收

- D1-01：轻量 Python 事实提供器识别单文件合约状态变量、函数/调用主体、修饰器、状态写、外部调用及等值检查，保留源码摘要、位置和顺序。注释与字符串不提供事实；未支持语义显式 PARTIAL/UNKNOWN，不能把 onlyOwner 名称或 require 字样直接当作有效防护。
- D1-02：Java 主模块定义独立检索接口，使用同一个有版本的候选池与预算运行 Dense、Hybrid、普通正反例和 D1；不读取测试标签，不触发模型调用。
- D1-03：案例条件通过明确的角色绑定匹配当前目标的主体、资源、作用域与顺序。有效检查、错误主体、错误资源、检查过晚、分支/旁路和未知分别有解释。动态别名、未知控制流不按名称猜测。
- D1-04：D1 在候选召回后选择经审核的漏洞/防护配对，配对须同机制、相同风险操作、对应条件且至少一项保护条件相反。过滤条件矛盾的直接支持，未知项保留原因；没有合格配对或预算不足时明确缺口，不编造案例。
- D1-05：证据包输出候选池摘要、策略、预算、所选块、支持/对比角色、逐条件绑定、未知原因和配对缺口。同一案例不重复选块；四种策略使用相同文本计量方法，预算硬限制。
- D1-06：离线确定性测试覆盖上述条件和排序/配对/去重/预算。保持 Maven 与 tools/experiment 全套通过，更新 PROGRESS 和验证证据。

### 已授权边界

保留 Java 主工程与 Python 事实适配器的现有设计，直接在主目录开发，保留未提交修改。新增解释与注释为简体中文。不修改旧 Milvus 集合；本地服务联通试验使用独立命名实例与合成向量，不能依赖外部 embedding/模型。真实数据来源、配对标签、效果比较和费用预算仍须审核，不在本轮自动扩大模型调用。

事实提供器是受限词法/结构分析，不是 Solidity 编译器、CFG 或漏洞证明器。D1 判断案例适用性，不裁决目标安全。目标角色显式指定并检查来源，不按变量名猜测谁是合法权限主体；权限状态槽需要调用方明确绑定。D2、正式假设生成及下游付费实验保留后续阶段。

状态：首个工程切片 FROZEN，2026-09-24（用户当日明确授权）；完整研究数据准入与 D1/D2 效果仍受 G1–G3 门禁约束。这不是论文题目或三研究内容冻结。学术依据见[第二轮裁决](../../../../thesis/D1_D2第二轮查新与立题裁决_20260924.md)，工程基线见 [S2 验证](VERIFICATION.md#s2-verification)。用户已授权直接在当前本地目录改工程，保留现有未提交修改；不建隔离工作树。

### 目标与非目标

目标：把 S2 的 D1 检索工程接到**可审计真实样本**，完成离线证据层的同预算可证伪先导；同时为高风险 D2 建立固定候选的 guard 覆盖挑战清单和可运行的简单基线。首期不承诺 D1/D2 方法已成立，不运行全面收费实验，不接完整多智能体、Foundry、Mythril 深度求解或全链 fork。

### 数据准入顺序

优先调查 SCRUBD 的重入真实案例、SmartBugs Curated 的隔离知识、ASE 2025 访问控制基准与 ACFix 的真实漏洞/补丁；来源可用性、公开许可、版本和负例质量必须逐项核验。SolidiFI 与旧名义安全合约仅用于 legacy 回归/故障测试，不作为正式外部真实性结果。真实补丁对、人工最小差异变体、合成夹具分开统计。首次先导样本规模按可靠独立项目数决定，不为达成 24 对目标引入伪标签。

### 研究门禁

G1：完成来源、标签与组隔离审计后，才准锁定开发先导。G2：离线 D1 与强基线比较，若仅字段过滤即可解释收益，D1 降级。G3：D2 只有固定真假候选和可审查保护路径证据时才进入方法原型；若既有过滤器达到相同双向错误/成本结果则暂停。G4：锁定测试只有在方法、阈值、tokenizer、提示和预算冻结后打开。不得因为临近开题日期绕过 G1–G3。

验证仍以离线测试为默认：根 Maven clean verify、Python unittest；真实 API/Milvus/工具须显式配置。先导实验与工程单元测试分别汇报。

### 目标和使用流程

论文作者在本机页面选择一个已登记的开发样本，查看正式 Milvus 快照与 D1 检索证据，选择离线演练或显式真实运行。系统按阶段展示初步漏洞假设、工具证据、D2 保护覆盖判断及失败原因，自动保存逐样本记录和可下载报告。作者能重开历史运行而不再次付费，并能从报告复核每个判断的源码和证据来源。

“完整”在本 Release 指**单个样本的工程链路完整**，不承诺任意合约自动审计、多用户部署、批量论文实验或 D1/D2 方法有效。页面显示 `researchEligible=false`，除非未来新的研究方案和准入证据另行冻结。

### 输入与数据隔离

- 仅列出固定首批分配清单中 `development` 且本机源码与登记 SHA-256 一致的目标。当前四项为 `AC-ASE-006`、`AC-ASE-009`、`RE-SCRUBD-001`、`RE-SCRUBD-002`。前两项源码分别约 5.8 KB、5.1 KB，可用于单次模型工程试跑，但现有轻量事实不含与正式访问控制知识对匹配的 `CALL`，D1 须显示“无可绑定风险操作”，不能声称条件检索成功。
- `RE-SCRUBD-001` 完整源码约 148 KB，允许对经原始行号定位的 `matchOrderWithReserve` 做**函数级**工程试跑：事实与工具读取完整源码，模型只读取这个约 5.9 KB 的函数及显式标注的行号；报告同时绑定完整源码摘要、函数片段摘要和行号范围，显示“上下文不完整”。D1 对该函数的调用事实仍为 `PARTIAL`，适用性未知不得升格为支持。`RE-SCRUBD-002` 约 60 KB，首版仍显示“超过提示上限”，不得静默截断成完整审计。函数级试跑不是完整合约检测，也不是论文样本结果。
- 知识与目标按项目、漏洞事件、补丁对、完全重复和近克隆关系隔离。目标 ID、源码摘要、分配版本和隔离报告必须绑定到运行计划；发现与正式知识样本同组、未知来源或跨划分关系时，拒绝检索和模型调用。开发样本的漏洞标签仍为待审，运行结果不得用作研究真值。
- 正式知识库只使用本机激活且通过完整性校验的 `s1b_` 快照，首版快照 ID 为 `9fc63d0e8828a8caa78145e133b8f954f9fedaf79469ea0927434d7dbef725c8`。旧 `mvp_` 集合继续只供历史工程演示；正式链路不得回退到它。新快照激活须仍经 S1b 的原子构建与全量读回程序，本 Release 不重建现有四条知识数据。
- 目标源码、报告和补丁仍按原谱系登记。知识修复片段代表特定风险位置的防御改动，不代表整个修复合约“安全”。

### 状态和计费边界

- 前端提供互不混淆的“离线演练”和“真实运行”动作，并显式区分整份源码与函数级范围。真实运行仅允许本机配置中既有的火山 Agent Plan 端点和已核实 DeepSeek 型号；端点、模型、样本、分析范围、快照、最大请求数、2048 输出 token 上限、零重试在点击前显示并写入计划。输入上限按完整请求的 UTF-8 字节硬控，不能宣称这等于实际 token 公平。
- 一次点击固定 `1 样本 × 1 D1 策略 × 1 重复 × 1 模型阶段 × 0 重试 = 最多 1 请求`。Slither/Mythril 在本地执行，不产生模型请求。批量实验需要另行冻结样本数、策略、重复次数、真实 tokenizer／模板和总请求及费用上界。
- 模型未报告漏洞时，系统结果只能称 `NO_CONFIRMED_FINDINGS`；D2 无法完整证实保护覆盖时不得改称安全。模型、工具或 D2 失败时保留对应阶段错误；最终结论 `UNRESOLVED`。报告区分 `COMPLETED`（流水线执行结束）、`FAILED`（执行故障）与判定 `UNKNOWN`（证据不足）。
- HTTP 服务只监听 `127.0.0.1`；状态和历史只允许本机访问；运行请求校验 Host、Origin、内容类型、请求体大小、样本白名单和单写者并发。客户端不得传入文件路径、模型端点、命令或知识库集合名。凭证只来自被 Git 忽略的本地配置或环境变量，绝不返回给页面或写入报告。

### 不包含

不接受任意上传源码、不开放公网或多用户权限；不自动下载样本、建立新的正式知识数据或打开锁定测试；不实施多智能体、深度路径求解或自动付费重试；不以本 Release 的工程运行计算 Recall@K、检测精度、D1 效果提升或 D2 错误率。研究对照仍按 R1-S3 的数据与 token 门禁单独进行。

### 验证与交付

先用完全离线的假快照／模型／工具完成成功、未知、超时、无效结构、数据库损坏、源文件变化和页面重放测试，再运行根 Maven 与 Python 全套离线测试。人工验收须核对页面所见的快照、候选、阶段、用量与 `.local/audit-runs/<runId>/` 文件一致，并确认只读操作不触发模型。每个可完成的小版本通过验证后，仅检查并提交该版本相关文件、排除凭证及既有用户未提交改动，再按仓库约定同步 `origin/main`。
