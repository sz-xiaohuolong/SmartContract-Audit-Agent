## 3. 每个阶段的关键任务包

### S0

- T0.1：留存旧输入输出夹具与版本，定义错误/未决/裁决数据；先写“空模型输出不能算 TN”失败用例。
- T0.2：重构进程执行器；使用本地受控短脚本模拟挂起、大量输出、异常退出和子进程。验证 deadline、输出上限与 cleanup，不调用真实合约分析器作唯一超时测试。
- T0.3：模型网关注入可替换客户端；模拟 429、401、无效 JSON、usage 缺失与中断。格式清理不丢 usage，也不生成默认安全结论。
- T0.4：默认测试排除真实 API/实验入口；模式所需依赖按需装配，Vanilla 不依赖 KB 导入；单元测试断网执行。

### S1

- T1.1：收集来源和项目谱系，生成只读原始清单；将 7 组完全重复以及同一基础注入变体归组。先不删原文件。
- T1.2：实现严格案例加载、稳定 ID 与构建 manifest，构造半导入失败并恢复；索引以新快照存在，旧集合不变。
- T1.3：将旧实验类的采样/调用/重试/计分/渲染拆开；阶段输出 JSONL，每条写入后可恢复。报告器只能读结果，不再调模型。
- T1.4：固定手算夹具验证多类别、重复预测、缺结果、未决和错误计数；比较旧 VTA 与新口径并解释差异。

### S2

- T2.1：选取经审核的小规模漏洞/防护案例，做条件 schema 和作用域事实夹具；错误主体、错误资源、检查过晚、旁路、未知均纳入。
- T2.2：实现共享召回接口及强对照，保存相同候选池和预算；D1 在此之上做绑定与互补选择。
- T2.3：完成普通正反例与 D1 的配对机制实验及错误分析；达不到差异条件时停止扩大模型调用。

### S3

- T3.1：建立机制义务模板和证据账本；先用固定目标源码/事实测试裁决表，避免模型提示掩盖逻辑问题。
- T3.2：实现缺口动作选择、去重和预算停止；先使用源码/静态事实补查，Mythril 仍明确是粗粒度辅助。
- T3.3：冻结相同假设集，跑普通验证、等预算自检和 D2；同时看错误接受、错误拒绝、未决及总覆盖，不只报 precision。

### S4

- T4.1：锁定配置、快照、提示、模型版本和重复数；检查测试标签从未进入运行侧。
- T4.2：完成四组消融和至少一个整项目/来源外测先导；记录不支持、运行失败和费用。
- T4.3：从结果文件重算报告，复查研究归因，列出开题可主张的内容与仍待验证的内容。

## 5. 提前收窄条件

- 前 5 个工作日仍无法获得稳定程序事实：D1 保留已支持语义范围，D2 先做可追踪源码补查；不假称完成 CFG/数据流证明。
- 无足够真实负例或访问控制数据：将其保留为机制测试，正式外测暂缓；由用户确认是否只保留重入作为首期。
- D1 与普通正反例效果相当：先检查标注与错误类型，确认后停止其创新主张，回到候选池，不扩大实验“找显著”。
- D2 仅靠增加未决降低误报：比较相同覆盖率与预算；没有独立改善则调整/淘汰方法。
- Mythril 环境不稳定：作为显式缺失工具记录，先完成源码/静态事实验证；不把少工具结果冒充 Full 对照。
- 套餐限流/额度不足：优先减少配置和非关键任务，保留必要重复与强对照；停止付费调度，不自动加购。

## 6. 实施与恢复纪律

每个任务采用“针对验收失败测试 → 最小实现 → 验证 → diff 复查 → 更新 PROGRESS”。创建工作区前检查用户 `.gitignore` 修改并保留，不能强行 reset/clean。数据和索引使用新版本，回退为配置切回旧产物。

同类失败三次、范围持续扩大或方法假设失效，记录 Debug Snapshot 并转 REPLAN_REQUIRED，不靠无限调参数继续。推送、PR、发布不包含在本轮或本提案的默认授权中。
