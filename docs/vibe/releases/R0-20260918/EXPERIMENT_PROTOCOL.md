# 数据治理与实验设计提案

状态：`PROPOSED`，2026-09-18；关联 REQ-02/05/06/08—16。本协议供审核，尚未冻结数据、阈值或统计假设。研究空白仍以原有 Phase4 文献复核为依据，本轮没有重新检索文献，也不宣称候选方法已经新颖。

## 1. 两条证据线

工程证据：运行状态正确、不会因超时卡死、数据不串集、记录可恢复、指标可重算。

科研证据：在公平预算和可靠标签下，D1 改善条件适用性与下游检测，D2 改善固定假设上的错误接受/错误拒绝及风险—覆盖权衡。工程修复必须在各比较组共享，不能把旧系统错误的修复算作 D1/D2 增益。

## 2. 数据来源分工

| 数据 | 用途 | 限制与准入 |
|---|---|---|
| 现有 400 份 SolidiFI / 名义安全样本 | legacy 回归、导入与故障处理冒烟 | 不能直接作为正式最终测试；存在重复、合成注入、来源捷径和安全标签未审核 |
| SmartBugs Curated / 现有 143 知识文档 | 旧 RAG 对照和经隔离后的部分知识来源 | 若用于 KB，不允许同项目/克隆/修复对进入测试；不能凭数据集名字不同认定隔离 |
| 可定位到审计报告、源码版本、修复的真实项目 | D1 适用性标注及正式外部评估候选 | 必须先核对公开许可、版本、机制和位置；没有下载/审核完成前不承诺样本数 |
| 专家复核的最小漏洞/防护配对 | 机制敏感性、作用域和错误类型测试 | 合成及人工改造单独报告，不冒充真实项目泛化 |
| 同源经审核负例 | FPR、错误接受和对比检索 | “没有已知报告”不等于安全；只对审核过的漏洞范围标负例 |

SCRUBD 的真实部分及其他真实审计项目是既有调研提出的候选来源，纳入前仍需本地许可、可编译性、标注质量与交叉重复核查。未解决的标签不能由同一个待测模型自动裁定。

## 3. 划分协议

先汇总所有候选来源，再构建关联图：项目/仓库谱系、同一基础合约及注入变体、漏洞与补丁对、完全重复和经复核的近似克隆为连边；连通组整体划分，不逐文件随机切。

初始组级比例建议 knowledge 50%、development 20%、validation 10%、test 20%；比例是审核后的起点，不强求在小样本上同时满足所有类别。测试应留出足够独立项目；若无法成立，则首月只做开发先导并报告限制。外部数据源整源/整项目留出，优先于凑固定比例。

- knowledge：可检索的案例、报告片段、修复及抽取模板来源。
- development：调代码、提示、条件规则与人工误差分析；可多次使用，不能称测试。
- validation：选阈值、预算、排序权重、停止规则；选择后冻结配置。
- test：一次性正式比较，不用于编写模板、修正提示或构造反例。
- train：首期不训练，因此为空；若以后引入训练，只能使用专门训练划分，并重新审核所有关联隔离，不能悄悄复用 test。

同项目的审计报告、补丁、函数切片、模型生成摘要和条件模板都继承组 ID；“源码删了但答案摘要仍在 KB”仍属泄漏。知识快照只能从 knowledge 构建。查询时动态排除 sampleId 无法替代预先隔离。

## 4. 去重与污染审计

1. 字节 SHA-256 与规范化源码哈希；保留原文件和转换清单。
2. 词法 Token 指纹/MinHash 产生候选，结合 AST/函数片段与来源关系复核；阈值在开发数据上设定。
3. 项目级图合并，人工处理大型标准库共享形成的过大组；记录是否为公共依赖而非直接将所有项目串成一组。不能只因同用 OpenZeppelin 就武断认定同项目。
4. 独立处理谱系：同一 SolidiFI 基础合约的不同类别注入变体必须在同组，重复文件不能当独立观测。
5. 去除类别目录、文件名、注入专用函数名/注释、已知答案说明的捷径。不能盲删所有注释：保留必要规范信息，做有/无答案标记的敏感性分析，转换前后可编译性及位置映射必须验证。
6. 可公开模型的训练集通常不可审计。报告“检索/评估隔离已检查”和“训练污染无法排除”；时间外测、重命名/等价变换、近期项目仅作缓解，不宣称完全消除。

当前检查只证明 7 组字节级重复、未见 KB 提取源码与测试的首尾空白标准化完全匹配。尚未完成近似克隆或项目关系审计，不能标记 dataset clean。

## 5. 标注最小单位

漏洞实例至少含：sourceHash、机制、路径/入口、位置、前提、影响资源、有效/无效保护证据、结论范围、原始出处和审核记录。

D1 标注案例—目标配对的条件可绑定性、风险适用性、保护差异及未知项；nDCG 需要事先定义相关性等级，例如 0=不适用、1=部分可用但缺关键条件、2=有实质支持或判别价值、3=可核验且补足关键条件。支持价值和对比价值可分别标注，不能把所有负例设为不相关。

D2 标注真假假设及条件事实；对无法判断的假设标 unknown，不加入声称完全标签的假设测试。建议关键样本由作者复核，争议例请导师或具备能力的第二审核者处理；在未完成独立复核前不报告“专家一致性”。模型能辅助提取，不替代标签真值。

## 6. 实验矩阵

### 6.1 工程回归与历史对照

保留 legacy 历史实现版本。新公共运行层统一修正状态、超时和计分后建立 corrected baseline；方法主比较全部使用 corrected 基础。历史报告只展示其原口径，不与新数字混同。

### 6.2 D1：检索质量与下游发现

对照：Vanilla、旧 dense 检索、hybrid（词法+向量）、通用重排、普通正反例、D1。所有检索组用相同知识快照、模型和最大上下文预算；排序模型额外调用计入总预算。

消融：去掉条件绑定；去掉适用性过滤；随机/普通反例替代判别反例；去掉互补选择；去掉程序事实但保留同预算文字分析。

衡量：条件相关 Recall@K/MRR/nDCG、有效反例率、Pair-Correct（有审核真值的配对两侧均判断正确的比例）、下游类型/实例 Precision、Recall、Macro-F1、FPR/FNR、成本。Pair-Correct 不能在无可靠配对的真实集硬造。

### 6.3 D2：固定假设的核验

先冻结各方法共享的同一批自然生成假设，保留原始证据和真假标签，验证器不得看到标签。按来自哪个发现器分层；人工构造错例作为压力测试另列，不替代自然误报。

对照：无验证、原最终裁决、等预算单模型自检、普通二次验证、Ranker/Critic 风格对照、基于威胁模型的验证对照、D2。对论文方法的自实现明确标“近似复现”，未经配置/数据核验不得用作者原文数字拼表。

消融：去掉条件覆盖；去掉程序事实；去掉补查；不区分缺失原因；固定动作顺序替代缺口驱动动作。建议保留一个“规则账本但无自适应补查”的强基线，区分结构收益与路由收益。

D2 的收益不能来自增加假设发现数量。独立固定假设实验完成后，再测端到端。真实漏洞根本未被发现器提出时，是发现漏报，必须计入端到端 Recall。

### 6.4 联合验证

2×2：普通检索+普通验证、D1+普通验证、普通检索+D2、D1+D2。同样本清单、模型、提示版本和预算；公共事实提取对各组可见性明确控制。D1/D2 单独实验的预算匹配不保证联合实验自动匹配，需分别配置并报告总成本。

## 7. 指标及错误处理

禁止继续用“异常→false”维持二分类表的表面完整性。

- 执行失败率：终态 FAILED 的请求数 / 所有计划请求数；同时列 PARTIAL、CANCELLED、未完成以及调用层失败。
- 裁决覆盖率：得到 SUPPORTED 或 REFUTED 的已标注假设数 / 所有已标注假设数。系统故障导致缺结果亦进入分母。
- 选择性错误率：已裁决中的错误比例；必须同时给覆盖率及整条风险—覆盖曲线。
- 错误接受率：假假设中被判 SUPPORTED 的数量 / 全部假假设。
- 错误拒绝率：真假设中被判 REFUTED 的数量 / 全部真假设。真但未决另计，不能用全部未决获得“零错误拒绝”的优越结论。
- 端到端漏洞实例 Recall：正确发现并支持的真实实例 / 测试集中全部目标真实实例；未生成、未决和失败对应真实实例均未被检出。
- Precision：正确支持实例 / 全部支持实例；不重复匹配，同一报告的重复预测多余项按预定规则计 FP。零分母显示未定义并列计数，不用 1 表示完美。
- 类型多标签指标：错误类型同时计真实类 FN、预测类 FP，宏平均采用预先冻结的有标注类别；不套用旧 VTA 的单侧错误计法。
- 负例误报率：已审核目标范围负例中至少一个错误支持实例的样本比例；再单列未决/失败率及“正确且完成 / 全部请求”，避免失败样本变相获益。
- 定位：依据原始文件+函数或行区间的预注册匹配准则；原始数据无位置时不计算位置得分。匹配按实例一对一，防重复计 TP。
- 成本：模型实际/估算输入输出 Token、所有重试、embedding 和离线构建成本分别列；工具调用率、p50/p95 延迟、超时率、缓存命中率。冷启动和缓存重放成本分别报告。
- Calibration Error：仅在定义了数值置信度且验证集校准后作为附加实验，不把自然语言 confidence 或自评直接当可比概率。

旧 VTA 可附录保留名称 `legacy_vta`，不能充当标准 Macro-F1。合约级未发现任何支持漏洞写“无已确认发现”，不自动赋值为经过证明的安全。

## 8. 统计与规模

先导建议 30—50 个经过复核的条件差异案例，仅用于问题存在性与流水线证伪，不作为正式显著性规模承诺。实际独立单位是项目/克隆组，不是变体文件数。

按项目组进行配对 bootstrap，报告 95% 区间与效应量；二分类配对检验需满足独立单位条件，多个变体不得当独立样本套 McNemar。多方法比较预先确定主比较并调整多重检验；稀有类别给计数和区间，不只给小数点后四位。

建议对重点配置至少 3 次独立模型运行估计随机性，但预算不足时减少配置数并保留重复，不能把同缓存重放算新重复。正式规模依据先导中的项目方差、最小有意义效应和可用数据决定。温度为零也不承诺云模型绝对确定性。

## 9. 预算与停止规则

每次实验先 dry-run 列样本数、模式数、重复数、预计调用与最坏预算。总调用上界至少覆盖：样本×配置×重复×每样本阶段调用×最大尝试数，另加离线抽取与 embedding；D2 补查需在每样本硬预算内。

先小批测真实限流和 usage，再批准扩大；预算不足自动停止调度，不悄悄换模型、降输入长度或修改测试样本。方舟 10 月 18 日到期是计划约束，不是所有后续调用免费的保证。

方法去留：若等预算强对照已解释全部收益、真实数据不支持假设错误机制、无法可靠审核负例、或实现成本超出月内预算，则暂停该候选并回到研究筛选。保留负结果，不制造“提升必须为正”的验收标准。
