# 智能合约漏洞速查表（Summary Cheat-Sheet）

> 说明：每条为单个短文档条目，适合做向量索引与快速检索。

## 1. Reentrancy（重入攻击）
**描述**：外部调用在修改合约状态之前发生；恶意合约可递归调用导致资金被多次提取。  
**关键字**：reentrancy, call(), send(), transfer(), external call before state update  
**检测提示**：检查存在 `call{value:...}("")` 或外部调用后再更新余额的模式。  
**缓解**：使用 Checks-Effects-Interactions 模式；使用 `ReentrancyGuard`。

---

## 2. Integer Overflow / Underflow（整数溢出/下溢）
**描述**：算术运算溢出导致错误的余额或阈值。  
**关键字**：+, -, * without SafeMath, unchecked arithmetic  
**检测提示**：未使用 SafeMath / Solidity 0.8+ unchecked 块。  
**缓解**：Solidity 0.8+ 原生溢出检查或使用 OpenZeppelin SafeMath（旧版）。

---

## 3. Access Control（权限控制错误）
**描述**：缺少 `onlyOwner` 或权限检查，敏感函数可被任意地址调用。  
**关键字**：public/external admin function, missing onlyOwner, tx.origin used for auth  
**检测提示**：函数带有管理行为但没有修饰器或 require 判断。  
**缓解**：使用角色管理（OpenZeppelin AccessControl / Ownable）。

---

## 4. tx.origin Authentication（使用 tx.origin 做权限判断）
**描述**：用 `tx.origin` 做权限验证会被钓鱼合约绕过。  
**关键字**：tx.origin == owner  
**检测提示**：在权限判断中出现 `tx.origin`。  
**缓解**：使用 `msg.sender` 与适当的修饰器/多签。

---

## 5. Unchecked External Call Return（未检查外部调用返回值）
**描述**：未检查 `call()` 或 ERC20 transfer 返回值可能导致失败被忽略。  
**关键字**：call(...); ERC20 transfer without checking return  
**检测提示**：对 `.call()` 未检查返回 `(bool success, )` 或未 require 返回值。  
**缓解**：检查返回值并 revert，或使用安全的接口包装。

---

## 6. Uninitialized Storage Pointer（未初始化存储指针）
**描述**：错误使用 `storage` 局部变量导致覆盖合约状态。  
**关键字**：`MyStruct storage s;` without assignment  
**检测提示**：局部声明 `storage` 未赋值。  
**缓解**：使用 `memory` 或正确赋值： `MyStruct storage s = array[index];`

---

## 7. Delegatecall Injection（delegatecall 注入）
**描述**：不受信任地址控制逻辑时使用 `delegatecall` 可导致逻辑/状态被篡改。  
**关键字**：delegatecall(target, data) with user-controlled target  
**检测提示**：存在 `delegatecall` 且 target 来自外部输入。  
**缓解**：避免不受信任地址的 delegatecall，或限制可调用的实现集合并校验。

---

## 8. Denial of Service (DoS) with Revert（拒绝服务 via revert）
**描述**：循环中对外部地址操作或单个地址 revert 能中断逻辑（如支付给所有用户）。  
**关键字**：for loop over users { user.call... }，push to array then external call in same tx  
**检测提示**：在循环里直接对外发钱或 trust untrusted callbacks。  
**缓解**：Pull-over-Push 模式（allow withdraw pattern），限制 gas 消耗。

---

## 9. Block Timestamp Dependence（时间戳依赖）
**描述**：用 `block.timestamp` 做关键随机或时间逻辑，易被矿工操控。  
**关键字**：block.timestamp used for randomness/lottery  
**检测提示**：随机或关键判断依赖 `block.timestamp` 或 `block.number` 可预测部分。  
**缓解**：使用可靠的预言机或链下/VRF 随机源。

---

## 10. Predictable Randomness（可预测随机性）
**描述**：使用 `blockhash`、`block.timestamp` 等生成随机数易被操控。  
**关键字**：keccak256(abi.encodePacked(block.timestamp, msg.sender))  
**检测提示**：基本链上元素被用作随机源。  
**缓解**：使用 Chainlink VRF 或安全随机源。

---

## 11. Unsafe ERC20 Handling（ERC20 不安全处理）
**描述**：忽略 ERC20 token 返回值或对非标准 token 假定行为（如不返回 bool）。  
**关键字**：ERC20 transfer assume success  
**检测提示**：直接 `token.transfer(...)` 不检查/不捕获返回值。  
**缓解**：使用 OpenZeppelin 的 SafeERC20。

---

## 12. Selfdestruct Misuse（selfdestruct 风险）
**描述**：允许任意人调用 `selfdestruct` 或发送合约以外资金到可被夺取地址。  
**关键字**：selfdestruct(owner) without proper guard  
**检测提示**：存在 `selfdestruct` 且无正确权限控制。  
**缓解**：避免公开 selfdestruct，权限严格控制。

---

## 13. Improper Input Validation（输入校验不足）
**描述**：对外部输入（长度、边界、索引）缺乏检查导致越界或逻辑错误。  
**关键字**：unchecked index access，no require length checks  
**检测提示**：数组索引、外部输入字符串/bytes 未校验长度。  
**缓解**：增加 `require` 检查与边界验证。

---

## 14. Gas Limit and Loops（Gas 限制与循环）
**描述**：未顾及大数据导致交易耗尽 gas 或失败（如遍历动态数组）。  
**关键字**：for i in dynamicArray { ... externalCall ... }  
**检测提示**：存在对不受限增长数组的全遍历操作。  
**缓解**：分页处理、使用映射或限制单次操作大小。

---

## 15. Front-running / MEV（抢先交易）
**描述**：交易顺序可被观察并抢先执行（如没有合并保护的交易会被抢先）。  
**关键字**：public tx triggers state change without protection  
**检测提示**：敏感操作没有防抢先机制（commit-reveal 或延迟）。  
**缓解**：采用 commit-reveal、打包或私有交易池等。

---
